协议漏洞、Web 攻击原理与安全防御

考点四是把"攻击"拆开讲原理的一页：伪基站利用 GSM 只认用户不认网络，三类 Flood 各打 TCP／UDP／ICMP 的弱点，缓冲区溢出利用程序不查长度，XSS 利用 Web 对输入的信任。原理搞清了，防御手段就是顺着原理反着做。

伪基站与 GSM 单向认证：手机从不验"网络是不是真的"

GSM 单向鉴权 2G 缺陷 3G 起双向认证
小区门禁只查"住户有没有卡"，从不验"开门的是不是物业"——于是骗子在旁边架一个假铁门，你的手机以为那是运营商的门，自己就走进去了。
伪基站是什么（定义原文）

伪基站是一种利用移动通信网络认证机制缺陷的非法无线电通信设备。GSM 网络存在自身安全缺陷，采用的是单向认证机制，不法分子利用这一脆弱性发送垃圾短信、诈骗短信。其手法是仿冒正常运营商 2G 网络的广播网号及频率，将周围手机的信号强行切换至其搭建的虚假网络中。

缺陷核心：只有网络验人，没有手机验网

在 GSM 系统中，只有网络对用户的认证鉴权机制，而缺乏用户对网络的认证。伪基站利用大功率压制或修改网络参数吸引终端加入，于是能：假冒号码群发短信、打电话；实施中间人攻击，在用户无感的情况下截获分析短信、电话并提取信息；提供假服务、钓鱼网站。

金融诈骗两种典型打法：仿冒真实客服号码下发诈骗短信，短信里的网址或客服电话与真实的不同，后台是钓鱼网站或虚假客服；或用改号软件仿冒客服号码，骗取用户银行卡信息。

排查与防御三条（大纲原文逐条）
防御手段具体做法
1 行为特征识别手机 App 预置伪基站特征数据，接入基站时判断基站状态与行为
2 建立伪基站数据库App 采集、上报基站信息，后台基于运营商基站信息完成识别
3 双向认证机制在用户终端和基站通信间建立双向认证，从源头杜绝非法伪基站

早期伪基站的四个特征要记：与正常基站 C1/C2 值差异显著；手机接入时间较短，造成大量手机位置更新；没有话音业务；存在大量相同长度短信业务。识别方法即一一对应：读 C1/C2 值、统计位置更新频度、监测独立专用信道信息、监测 LAI 值。

02

三类 Flood：SYN 占队列、UDP 抢带宽、ICMP 堵线路

SYN Flood UDP Flood ICMP Flood DoS / DDoS
三种堵车方式：SYN 是假装排队占着窗口不结账，UDP 是大货车满载抢道把路压垮，ICMP 是全城疯狂按喇叭把耳朵吵聋。打的协议不同，堵法不同，堵点也不同。
DoS 与 DDoS（先分清两个词）

拒绝服务（Denial of Service, DoS）攻击是指攻击者通过某种手段使目标系统无法向合法用户提供正常服务的攻击行为。分布式拒绝服务（DDoS）攻击则利用多个被控制的主机同时发起攻击。

SYN Flood：利用 TCP 三次握手的缺陷

它是当前网络上最为常见的 DDoS 攻击，也是最为经典的拒绝服务攻击，利用了 TCP 协议实现上的缺陷。攻击链：

攻击链：伪造大量源 IP → 向目标端口发 SYN → 服务器回 SYN+ACK → 伪造源地址收不到回应 → 服务器重试并等待 SYN Timeout 后丢弃 → 半开连接队列被占满 → 合法用户进不来

防御三条：① SYN Cookie 技术——服务器不分配半连接资源，而是通过加密算法生成初始序列号，待客户端完成 ACK 后验证合法性，是防御 SYN Flood 的重要发展方向；② TCP 代理防御及 TCP 源探测防御；③ 连接队列优化与硬件防火墙——调整半连接队列参数，采用具备 SYN 代理功能的防火墙。

UDP Flood：流量型 DoS，打的是"无连接"

通过伪造源 IP 向目标设备发送大量 UDP 报文，利用 UDP 协议无连接特性消耗目标网络带宽及系统资源，导致服务中断。UDP 是无会话协议，需要很少的资源即可执行；常见情况是利用大量 UDP 小包冲击 DNS 服务器或 RADIUS 认证服务器——攻击者把 UDP 包发至随机端口，迫使目标消耗资源处理无效响应。

防御三条：① 速率限制——对单个源 IP 的 UDP 包速率进行限制；② 流量清洗——部署专业的 DDoS 防护设备进行流量清洗；③ 端口过滤——现代防火墙会丢弃发往关闭端口的 UDP 流量。

ICMP Flood：Ping 包塞满线路

攻击者向目标系统发送大量 ICMP Echo 请求（Ping 包），目标系统需要对每个请求进行响应。由于 ICMP 协议本身没有流量控制机制，攻击者可以发送超大尺寸或高频率的 ICMP 包，造成网络拥塞和潜在的服务拒绝。

防御三条：① 禁用 ICMP 响应——在防火墙上限制或禁用 ICMP Echo 响应；② 流量限速——对 ICMP 流量进行速率限制；③ 入侵检测——部署 IDS/IPS 检测异常的 ICMP 流量模式。

03

缓冲区溢出：水溢出瓶子泡湿图纸，三道防护各堵一段

缓冲区溢出 栈金丝雀 NX 位 ASLR
往 500ml 的瓶子里灌 1 升水，多余的水漫出来泡湿旁边摊着的图纸——瓶子是缓冲区，图纸是相邻内存里的返回地址。图纸一被改掉，程序就转去执行攻击者写的指令。
定义与后果

缓冲区溢出是指向程序的缓冲区输入超出其容量的数据，导致数据溢出并覆盖相邻内存空间，从而破坏程序的正常运行，甚至可能使攻击者获取程序或系统的控制权。它非常普遍、非常危险，在各种操作系统、应用软件中广泛存在；后果是程序运行失败、系统宕机、重新启动。

攻击原理：病根是"没查输入长度"

通过向一个有限空间缓冲区复制过长的字符串，从而破坏程序的堆栈，使程序转而执行其他指令。造成缓冲区溢出的原因是程序中没有仔细检查用户输入的参数。攻击者可以写入已知可保存可执行代码的区域并将其替换为恶意代码，或有选择地覆盖与程序状态有关的数据。

防御一：写安全代码（从源头不灌水）

对缓冲区读或写时，对读写数据长度进行检查，确保读写的内存在被分配的内存空间之内；切换到有界字符串操纵函数；确保在可能发生溢出的行之前插入验证条件。

防御二：编译器与操作系统三层硬防护（考点核心）
机制全称 / 位置防住什么
栈金丝雀（Stack Canary）编译器层，基于 Canary 的栈保护技术溢出时金丝雀值被覆盖即程序崩溃，阻止返回地址被篡改；简单有效且广泛部署
NX（No-Execute）位CPU 硬件层面防止数据页中的代码被执行——灌水进数据区，那段"水"也跑不起来
ASLR（地址空间布局随机化）操作系统层随机化内存地址布局，攻击者猜不到跳板地址，增加攻击难度

三者是叠加关系：金丝雀管"别改返回地址"、NX 管"数据区不许执行"、ASLR 管"找不到目标地址"——一个挡不住，还有后两道。

防御三：程序检测与数据结构设计

从程序编写、程序检测、数据结构设计以及程序执行控制等多个角度，对防止缓冲区溢出攻击进行分析，提出遏制利用缓冲区溢出漏洞的方法。

一句话记

溢出的病根是"不查长度"：代码先查，金丝雀盯栈，NX 禁执行，ASLR 乱地址——四道闸一道都不能少。

04

XSS 三类：回显一次、落库一片、前端自己跑

反射型 存储型 DOM 型 输出编码 · CSP · HttpOnly
你在论坛发了一段"会动的字"，网站没当回事原样贴出去，一万个访客打开页面时浏览器把这段字当命令执行了——Cookie 就是这样被偷走的。
XSS 是什么

跨站脚本攻击（Cross-Site Scripting，简称 XSS）是一种通过注入恶意脚本代码实现非授权操作的 Web 安全漏洞。它是 Web 应用的最大威胁之一，不仅危害应用本身，也对访问的用户带来直接影响。其本质是 Web 应用对用户输入的信任导致恶意代码执行。被利用时，攻击者可以执行会话劫持、窃取 Cookie、恶意重定向等操作。

攻击链三步（所有类型共用）
攻击链：输入注入（URL 参数 / 表单提交 / HTTP 头 / Cookie）→ 输出渲染（未安全处理，直接嵌入 HTML、JavaScript 或 DOM）→ 浏览器执行（用户访问受污染页面，解析执行恶意脚本）
三种类型：触发位置是判分类的唯一标准
类型触发位置是否落库典型场景
反射型（非持久型）服务端回显：脚本通过 URL 或表单提交直接返回给用户不存储在服务器端搜索功能把用户输入参数直接拼接到 HTML 中
存储型（持久型）数据库落库：脚本存进服务器数据库持久化存储论坛评论区、留言板等用户输入被持久化的功能；所有访问该页面的用户都受影响
DOM 型前端 DOM 执行：攻击发生在客户端，修改页面 DOM 结构执行脚本无需服务器参与前端把 URL 参数、hash 直接写进 DOM
防御四条（大纲逐条）

① 输入验证与过滤——对所有用户输入严格白名单验证，只允许已知、安全的字符或格式通过；
② 输出编码（核心防御）——将数据输出到 HTML 页面时，必须根据上下文进行相应的编码或转义；研究表明输出编码和内容安全策略是保护 Web 应用免受 XSS 攻击最有效的方法；
③ 内容安全策略（CSP）——在 HTTP 响应头中设置 Content-Security-Policy，明确告诉浏览器允许加载哪些域的资源，实现严格 CSP 是利用 CSP 缓解 XSS 漏洞的最佳方法；
④ 安全 API 与 HTTP-only Cookies——使用 DOMPurify 等库净化 HTML，避免直接使用 innerHTML 等不安全方法；设置 HTTP-only Cookies 防止通过 JavaScript 窃取会话 Cookie。

一句话记

反射是"当场弹一次"、存储是"进库害一片"、DOM 是"前端自己跑"；根治靠输出编码兜底，CSP 加 HttpOnly 双保险。

05

暴力破解的痕迹识别与勒索软件"九要"

暴力破解 低频持续 勒索九要 应急处置
小偷拿一串钥匙挨把试门锁：白天连试十次你马上会发现；改成每天夜里悄悄试一把、连试半年，你根本注意不到——破解不可怕，可怕的是它藏在时间里。
暴力破解是什么、日志里长什么样

暴力破解攻击是指攻击者通过系统地组合所有可能性（例如登录时用到的账户名、密码），尝试所有的可能性破解用户的账户名、密码等敏感信息，常使用自动化脚本组合出正确的用户名和密码。

三类日志痕迹：① 高频登录失败——同一 IP 在短时间内出现大量登录失败记录；② 固定凭证模式——长期、反复使用同一账号和错误密码尝试登录；③ 多服务尝试——同一主机尝试暴力破解多种服务。另外还有一种"低频、持续、固定凭证"模式：每天以极低频率尝试登录，极具迷惑性。

时间特征最关键：给攻击者留的时间越长，其组合出正确用户名和密码的可能性就越大——所以破窗要早。

排查三法与防御四条

排查：① 日志审查——检查暴力破解检测模块日志可清晰发现攻击 IP；分析网络日志、抽取安全事件、捕获异常行为特征、构建特征规则；② 关联分析与时间线还原——按时间、IP、用户、操作类型等维度关联，识别攻击链中的连续动作，按时间顺序梳理事件、标记关键节点；③ 流量分析——网络全流量采集协议元数据，清理后发大数据平台，用 Wireshark 等工具做网络取证分析。

防御：账户锁定策略（设登录失败次数阈值，超过后锁定账户或 IP）、双因素认证（密码之外的第二层身份验证）、强密码策略（高强度且无规律）、实时监控与告警（部署规则检测暴力破解等攻击）。

勒索软件概述

勒索软件是黑客用来劫持用户资产或资源实施勒索的一种恶意程序：通过加密用户数据、更改配置等方式使用户资产或资源无法正常使用，以此为条件要求支付费用，以获得解密密码或恢复系统正常运行。

CNCERT《勒索软件防范指南》"九要"（九条一条不能少）
#要核心动作
1要做好资产梳理与分级分类管理清点信息系统和应用程序、建立资产清单；识别关键业务和关键系统，确定应急响应优先级
2要备份重要数据和系统定期备份并采取隔离措施，严格限制对备份设备和备份数据的访问权限，防止勒索软件横向移动加密备份
3要设置复杂密码并保密高强度无规律密码，含数字、大小写字母、符号，长度至少 8 位，经常更换
4要常杀毒、关端口安装杀毒软件并定期更新病毒库、定期全盘杀毒；关闭不必要的服务和端口
5要做好身份验证和权限管理加强访问凭证管理，建议双因子身份认证；细化权限，遵守最小特权原则
6要严格访问控制策略加强网络隔离、使用网络分段；严格远程访问管理，如无必要关闭所有远程管理端口
7要定期安全风险评估定期风险评估与渗透测试，识别并记录资产脆弱性，及时修复安全漏洞
8要提高人员安全意识为组织内人员和合作伙伴提供网络安全意识教育
9要制定应急响应预案针对重要系统制定预案，明确应急人员与职责、应急和恢复方案，定期开展演练

九要口诀：资产、备份、密码、杀毒关端口、身份权限、访问控制、风险评估、人员意识、应急预案。

感染后的应急三步

① 隔离网络——拔掉网线或禁用网络，切断受感染机器连接，避免其他机器被进一步感染渗透；② 分类处置与及时报告——根据感染情况分类处置，及时向相关部门报告；③ 排查加固与专业恢复——分析清楚入侵途径并及时加固堵塞漏洞，必要时请专业安全公司协助恢复。

DOM 型 XSSCSP

单页应用读取 location.hash 后用 innerHTML 渲染"欢迎语"，服务器从头到尾没参与，后端日志一片干净。

落地动作：改用 textContent 或 DOMPurify 净化；响应头加 Content-Security-Policy，如 default-src 'self'，禁掉未授权域脚本与内联脚本。

挂的知识点：DOM 型 XSS——攻击发生在客户端、通过修改 DOM 结构执行脚本、无需服务器参与；防御对应安全 API 与 CSP。

被 XSS 偷走的会话 Cookie 还能抢救吗

漏洞已经在线上跑着，Cookie 被脚本读走拿去冒充登录，后台发现陌生会话。

落地动作：会话 Cookie 设置 HttpOnly，让 JavaScript 读不到；Cookie 加 SameSite 与短期有效期；登录态与 IP／UA 绑定异常告警；批量强制下线重登。

挂的知识点：XSS 后果＝会话劫持、窃取 Cookie；HTTP-only Cookies 防止通过 JavaScript 窃取会话 Cookie。

C 程序收姓名框，不量长度直接 strcpy

表单"姓名"字段能填 1000 个字符，后端缓冲区只有 500 字节，超长输入把相邻内存全盖了。

落地动作：读写缓冲区先检查数据长度；用有界字符串函数（如 strncpy）；编译开启栈金丝雀；测试环境加 NX 与 ASLR，fuzz 长字符串验证。

挂的知识点：缓冲区溢出病根＝程序没有仔细检查用户输入参数；栈金丝雀是简单有效且广泛部署的防御手段。

组二 · 运维值班 / 网络防护

凌晨网站白页，半开连接队列被占满

监控告警 80 端口积压：大量半开连接，源 IP 全是伪造地址，合法用户三次握手完不成。

落地动作：服务器开启 SYN Cookie（不分配半连接资源，ACK 后再验证合法性）；上线具备 SYN 代理功能的硬件防火墙；调整半连接队列参数；配合 TCP 源探测确认真实客户端。

挂的知识点：SYN Flood 利用 TCP 三次握手缺陷占满半开连接队列；防御三件套＝SYN Cookie、TCP 代理／源探测、队列优化。

DNS 服务器被 UDP 小包冲爆

出口带宽打满，抓包一看全是伪造源 IP 的 UDP 小包，目标端口随机。

落地动作：对单个源 IP 限制 UDP 包速率；部署专业 DDoS 防护设备做流量清洗；防火墙丢弃发往关闭端口的 UDP 流量；DNS 递归服务只对可信内网开放。

挂的知识点：UDP Flood 利用 UDP 无连接特性消耗带宽，常见冲击 DNS 与 RADIUS 服务器；防御＝限速、清洗、端口过滤。

监控大屏被巨大 Ping 包塞满

网络设备 CPU 告警，抓包全是超大尺寸 ICMP Echo 请求，每个都得回一个。

落地动作：在防火墙上限制或禁用 ICMP Echo 响应；对 ICMP 流量做速率限制；部署 IDS/IPS 检测异常 ICMP 流量模式；对外服务器不必响应 Ping。

挂的知识点：ICMP Flood 利用 ICMP 本身没有流量控制机制，超大尺寸或高频率包造成拥塞。

22 端口暴露公网，日志刷爆登录失败

ssh 日志里同一 IP 短时间几百次失败，还反复用同一账号试，典型自动化脚本。

落地动作：22 端口只对堡垒机开放；登录失败 5 次锁定 IP 15 分钟；启用双因素认证；默认管理员账号改名、禁用 root 直登；部署规则实时告警。

挂的知识点：暴力破解日志特征＝高频登录失败、固定凭证模式、多服务尝试；防御＝账户锁定＋双因素＋强密码＋实时监控。

日志每天只有零星失败，半年后被登进来了

每天极低频率试几次同一账号，按"分钟窗口"告警永远触发不了，攻击者慢慢试出来了。

落地动作：按天／按周聚合统计失败次数做长周期关联；把同一账号＋同一错误口令模式标记为可疑；日志按时间、IP、用户、操作类型还原时间线；全流量留存供 Wireshark 取证。

挂的知识点："低频、持续、固定凭证"型攻击极具迷惑性；时间给得越长，试出正确密码概率越大。

组三 · 个人用网 / 金融场景

收到"建行客服"短信，链接长得像官网

展会现场人挤人，手机突然没信号，接着收到 106 开头短信："您的建行 E 盾过期，点击更新"，附带网址。

落地动作：不点短信里的链接、不打短信里的电话；打开官方 App 或自行输入官网核对；看到网址域名、号码与真实不符即判定仿冒；向 12321 举报。

挂的知识点：伪基站金融诈骗＝仿冒真实客服号码下发短信，后台是钓鱼网站或虚假客服；识别看 C1/C2 值、位置更新、无话音业务。

手机突然只显示 2G，信号格满但上不了网

景区门口信号"很好"，手机却频繁位置更新，只收到同长度的垃圾短信，没有电话进来。

落地动作：立即开关飞行模式回到 4G/5G；手机设置里关闭"仅 2G 优先"；2G 时代的伪基站只骗只认 2G 的终端，3G 起双向认证后假网络过不了 AKA 这一关。

挂的知识点：伪基站特征＝大量位置更新、无话音业务、大量相同长度短信；3G UMTS 用 AKA、4G 用 EPS-AKA、5G 用 5G-AKA 和 EAP-AKAˈ 双向认证。

家里路由器后台被人远程试密码

路由器管理日志显示境外 IP 反复尝试 admin 登录，密码还是出厂 admin。

落地动作：密码改成长度至少 8 位、含数字大小写字母符号的复杂密码并经常更换；关闭远程管理端口（如无必要）；固件及时更新；WAF 式规则拦同 IP 高频失败。

挂的知识点：勒索"九要"之要三（复杂密码）与要六（无必要关闭所有远程管理端口）；同时呼应账户锁定防御。

组四 · 应急现场

财务电脑文件全变成 .locked，弹窗要赎金

上午九点财务打开电脑，所有表格加了后缀，桌面弹出付款页面，限时 48 小时。

落地动作：立刻拔网线、禁用网络切断连接（防横向感染）；保留样本、别重启别格盘；按感染情况分类处置并及时上报相关部门；分析入侵途径、加固堵塞漏洞，必要时请专业安全公司协助恢复；严禁直接付赎金。

挂的知识点：勒索软件感染后应急三步＝隔离网络、分类处置与及时报告、排查加固与专业恢复。

备份盘一直插在服务器上，也被一起加密了

以为有备份就安全，结果勒索软件横向移动把映射盘上的备份也加密干净，恢复无路。

落地动作：备份采取隔离措施（离线／异地／断网保存）；严格限制备份设备与备份数据的访问权限；定期恢复演练验证备份可用。

挂的知识点：九要第二条"要备份重要数据和系统"原文——严格限制对备份设备和备份数据的访问权限，防止勒索软件横向移动对备份数据进行加密。

组五 · 面试 / 监管检查

面试被问"反射型、存储型、DOM 型 XSS 怎么区分"

只答"一个是弹出来的、一个是存起来的"，面试官追一句"那防御有区别吗"就卡壳。

落地动作：按触发位置答——反射是服务端回显一次、存储是数据库落库害一片、DOM 是前端 DOM 执行无需服务器；防御统一收束到"输入白名单＋输出编码（核心）＋CSP＋HttpOnly"。

挂的知识点：XSS 三类触发位置表；输出编码与 CSP 是最有效方法。

检查组问"你们防勒索软件怎么做的"

答"我们装了杀毒软件"只有一条，对照清单八条没了。

落地动作：背出九要——资产梳理分级、隔离备份、复杂密码、杀毒关端口、双因子与最小权限、网络分段关远程端口、定期风险评估与渗透测试、人员意识教育、应急预案与演练；再补感染后三步（隔离网络、分类处置上报、排查加固恢复）。

挂的知识点：CNCERT《勒索软件防范指南》九要全部条目；感染后应急三步。
