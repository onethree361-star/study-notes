数据库与数据治理

一句话：数据库是"存数据的仓库"，核心是三级模式保证独立性、ACID 保证事务可靠、SQL 是操作语言。数据治理是在仓库之上加安全、备份、性能优化。

考点1 · 数据库系统

组成 · 结构 · 特点 · 设计

一、数据库系统组成

数据库系统（DBS）= DB + DBMS + 应用系统 + DBA + 用户，其中 DBMS 是核心。

术语是什么一句话
DB数据库有结构、统一存储的数据集合，集成+共享
DBMS数据库管理系统管数据库的系统软件，是 DBS 的核心
DBA数据库管理员负责设计、维护、调优的人
DBS数据库系统包含硬件+软件+人+数据的完整系统

二、数据库系统结构：三级模式 + 数据模型

三级模式：外模式（用户视图，多个）→ 模式（全局逻辑，唯一）→ 内模式（物理存储，唯一）。两级映像保证独立性。

数据模型三要素：数据结构 + 数据操作 + 完整性约束。三类模型：概念模型（E-R）、逻辑模型（层次/网状/关系）、物理模型。

逻辑独立性：模式改了，改外模式映像，应用不变。物理独立性：内模式（存储）改了，改模式/内模式映像，应用不变。

三、数据库系统基本特点

特点含义
数据集成性统一全局模式，多个视图共享，减少冗余
数据共享性高多用户、多应用同时用同一数据
数据独立性高逻辑独立性 + 物理独立性，应用不随存储变
统一管理控制安全性、完整性、并发控制、故障恢复

三类完整性约束：实体完整性（主键不为空）、参照完整性（外键要么空要么参照已存在）、用户定义完整性（字段有效性）。

四、数据库：设计流程 · 对比 · 候选码 · 范式

数据库设计流程（六阶段）：需求分析 → 概念设计（E-R图）→ 逻辑设计（转关系表）→ 物理设计（索引/存储）→ 数据库实施 → 运行维护。

数据库对比：

类型代表特点适用
关系型MySQL/Oracle表格结构，ACID，强一致日常事务（OLTP）
NoSQLMongoDB/Redis灵活 schema，高扩展，弱一致大数据、高并发
图数据库Neo4j节点+边，擅长关系穿透社交网络、反洗钱

候选码：能唯一标识元组的最小属性集（不能再删）。冗余：同一信息重复存多处，导致更新/插入/删除异常。

范式（设计规范，级别越高冗余越小）：

范式规则消除什么
1NF每个属性不可再分（原子值）属性可拆分导致混乱
2NF在1NF上，非主属性完全函数依赖于主键（不部分依赖）部分依赖冗余
3NF在2NF上，非主属性不传递依赖于主键传递依赖冗余

例：学生(学号,姓名,系,系主任)——系主任传递依赖于学号，违背 3NF。拆成 学生(学号,姓名,系) + 系(系,系主任)。

考点2 · SQL操作

命令分类 · 查询 · 操作 · 定义 · 控制

2.0 SQL 命令、子句、函数总览表

分类关键字功能
DQL 查询SELECT查数据
DML 操纵INSERT / UPDATE / DELETE增删改数据
DDL 定义CREATE / DROP / ALTER建表、建索引、改结构
DCL 控制GRANT / REVOKE授/收权限
SELECT 子句作用顺序
FROM从哪张表1
WHERE行级筛选（分组前）2
GROUP BY分组3
HAVING组级筛选（分组后）4
ORDER BY排序，最后5

WHERE vs HAVING：WHERE 在分组前筛行，HAVING 在分组后筛组。COUNT(*) 含 NULL，COUNT(列名) 不含 NULL。

一、数据查询（DQL）

SELECT [DISTINCT] 目标列
FROM 表名
WHERE 条件
GROUP BY 分组列
HAVING 分组后筛选
ORDER BY 排序列 [ASC|DESC];

条件谓词：=、>、<、BETWEEN...AND、IN、LIKE 模糊匹配（% 任意多字符，_ 单个字符）。

多表连接：

连接结果
INNER JOIN只返回两表匹配的行（交集）
LEFT JOIN左表全保留，右表不匹配补 NULL
RIGHT JOIN右表全保留，左表不匹配补 NULL
FULL JOIN两表全保留，不匹配都补 NULL

嵌套查询：WHERE 里套 SELECT。EXISTS / NOT EXISTS：只判断"有没有满足条件的行"，不关心具体值。

聚合函数：COUNT、SUM、AVG、MAX、MIN，通常配合 GROUP BY 使用。

二、数据操作（DML）

INSERT INTO 表(列) VALUES(值);
UPDATE 表 SET 列=值 WHERE 条件;
DELETE FROM 表 WHERE 条件;

DELETE 是按行删，可回滚；DROP 是删表，不可恢复。

三、数据定义（DDL）

建表：CREATE TABLE，列级/表级约束。索引：CREATE [UNIQUE] INDEX，加速查询但占空间。

CREATE TABLE 学生(
  学号 CHAR(9) PRIMARY KEY,
  姓名 CHAR(20) NOT NULL,
  系 CHAR(20),
  UNIQUE(姓名)
);
CREATE INDEX 索引名 ON 表(列);

四类完整性约束：PRIMARY KEY（主键）、UNIQUE（唯一）、NOT NULL（非空）、FOREIGN KEY（外键）。

四、数据控制（DCL）

GRANT 授权，REVOKE 收权。

GRANT SELECT ON TABLE 学生 TO U1 WITH GRANT OPTION;
REVOKE SELECT ON TABLE 学生 FROM U1 CASCADE;
关键字含义
WITH GRANT OPTION允许被授权者再转给别人
CASCADE级联收回（连转给别人的一起收）
RESTRICT限制收回（若已转授则拒绝执行）

角色（Role）：把一组权限打包成角色，授予用户，方便批量管理。

考点3 · 数据库运维设计

事务安全 · 性能优化

3.A 事务与安全运维

事前：事务与并发控制

事务 = 一组操作，要么全做要么全不做。四个属性（ACID）：

属性含义
A 原子性不可分割，全做或全不做
C 一致性执行前后数据库从一个一致状态到另一个
I 隔离性多事务并发，互不干扰
D 持久性提交后永久生效，崩溃也不丢

并发问题：丢失修改、脏读、不可重复读（UPDATE引起）、幻读（INSERT/DELETE引起）。

封锁机制：X锁（排他/写，独占）、S锁（共享/读，可并发读）、U锁（更新，避免死锁）。

事前：内部安全访问控制

层级措施
身份鉴别强密码、IP白名单、多因素认证
角色 RBAC先建角色绑权限，用户关联角色批量授权
行级 RLS不同人只看本分片数据，敏感字段脱敏

四大原则：最小权限、权限随岗位变动回收、职责分离、高危操作双人复核。

事前：整体安全控制体系

网络隔离（防火墙、堡垒机）+ 传输加密（SSL/TLS）+ 透明数据加密（TDE）+ 全量审计日志 + 高危变更审批（CR+CCB）。

事中：运维监测体系

监控项盯什么
资源指标CPU、内存、磁盘 IO、连接数、锁等待
异常行为异地登录、爆破、全表导出、慢 SQL
故障链路主从同步、主库宕机、备份文件完整性
操作留痕堡垒机全程录屏、SQL 日志全记录

事后：备份与恢复体系

行业 3-2-1 原则：至少 3 份副本、2 种介质、1 份异地。

备份方式备份内容特点
全量备份整个库恢复最简单，慢、占空间大
增量备份上次备份后变化快、小，恢复要按顺序串
差异备份上次全量后所有变化恢复只需全量+最近一次差异
日志归档事务日志最小粒度，支持任意时间点回退

恢复分级：误删表 → 备份+日志回退；硬盘损坏 → 异地副本整库还原；机房灾难 → 跨机房灾备。

3.B 性能优化（7招）

一、索引设计优化

索引是 B+ 树结构，用额外空间换查询速度。五类索引：主键、唯一、普通、联合（复合）、覆盖。

黄金原则：高频查询/排序/分组字段优先建；低区分度字段（性别）别建；避免索引列上用函数/运算；联合索引遵循最左前缀。

二、SQL 查询优化

别 SELECT *；用 WHERE 先缩小范围；大分页用主键回溯；小表驱动大表；避免大事务和慢 SQL。

三、数据库缓存优化

磁盘 IO 是最大瓶颈，把高频热点数据、查询结果预存到内存，下次直接从内存取，不用读磁盘。

层级技术缓存什么
内置缓存InnoDB Buffer Pool表页、索引热点页，占物理内存 50%~80%
分布式缓存Redis热点业务数据、高频查询结果、会话

缓存三原则：① 只读热点优先，频繁变更少缓存；② 设合理有效期；③ 杜绝缓存与数据库长期不一致。

四、数据表分区优化

大表拆成多个物理分区，逻辑上还是一张表。四种方式：范围（按时间/数值）、列表（按枚举值）、哈希（均匀打散）、键分区。

五、读写分离架构优化

主库负责写，从库负责读，通过 binlog 实时同步。一主多从，中间件自动路由。

六、负载均衡优化

读均衡：多从库按权重分发请求。写均衡：分库分表拆写入压力。垂直扩容（升硬件）+ 水平扩容（加节点）。

七、服务与存储层优化

监控 CPU/内存/磁盘/连接数；数据文件、日志、索引分到不同高性能磁盘；短期靠升级硬件，长期靠架构优化。

考点4 · 数据仓库与数据挖掘算法

OLTP vs OLAP · 算法 · 评估

一、数据仓库

维度OLTP（联机事务处理）OLAP（联机分析处理）
面向具体业务（存钱、下单）宏观分析（销售趋势、风险）
数据细节、当前、经常更新综合、历史、相对稳定
单次量小大
响应要求极高相对宽松

四种存储：关系库（OLTP）、数据仓库（OLAP）、图数据库（Neo4j，社交网络/反洗钱）、流数据库（实时流）。

二、数据挖掘

监督学习：有标签，预测新样本。无监督学习：无标签，发现结构。

任务类型代表算法干什么
分类监督决策树、Logistic、SVM、朴素贝叶斯预测类别（垃圾邮件？）
回归监督线性回归、岭回归预测连续值（房价？）
聚类无监督K-means、DBSCAN自动分组（用户分群）
关联分析无监督Apriori发现共购（买A常买B）
降维无监督PCA高维转低维，减少维度灾难

K-means 步骤：选 K 个中心 → 样本归最近中心 → 重算中心 → 迭代到收敛。

三、模型评估

二分类用混淆矩阵：

预测正预测负
实际正TP 真正例FN 假负例
实际负FP 假正例TN 真负例
指标公式含义
准确率 Accuracy(TP+TN)/总数整体猜对比例
精确率 PrecisionTP/(TP+FP)预测为正中，真对的比例
召回率 RecallTP/(TP+FN)真样本中，被找出来的比例
F12×P×R/(P+R)精确率与召回率的调和平均

ROC 曲线：横轴假正例率（FPR），纵轴真正例率（TPR=召回率）。越靠左上角越好。AUC 是 ROC 下面积，0.5=瞎猜，>0.8=好，>0.9=优秀。不平衡数据集用 AUC 比准确率稳。
