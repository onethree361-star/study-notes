数据库与数据治理

一句话：数据库是"存数据的仓库"，核心是三级模式保证数据独立性，ACID 保证事务可靠，SQL 是操作语言。数据治理是在仓库之上加安全、备份、性能优化。

一、数据库系统基础

概念 · 范式 · 三级模式 · E-R

1.1 核心概念

DB（数据库）= 有统一结构、统一存储的数据集合，特点是集成 + 共享。DBMS（管理系统）= 管数据库的软件，是 DBS 的核心，属系统软件。DBA = 管库的人。DBS = DB + DBMS + 应用 + DBA + 用户。

术语是什么一句话
DB数据库存数据的地方，集成+共享
DBMS数据库管理系统管库的软件，系统软件
DBA数据库管理员设计+维护+调优
DBS数据库系统DB+DBMS+人+应用，以 DBMS 为核心

特点：集成性（全局模式+局部视图）、共享性高冗余低、独立性高（逻辑+物理）、统一管理（安全+完整+并发）。

1.2 范式 1NF / 2NF / 3NF

范式是设计表的规范，级别越高冗余越小。目的是消除插入/删除/更新异常。

范式规则消除什么
1NF每个属性不可再分（原子值）属性可拆分导致的混乱
2NF在 1NF 上，非主属性完全函数依赖于主键（不部分依赖）部分依赖导致的冗余
3NF在 2NF 上，非主属性不传递依赖于主键传递依赖导致的冗余

例：学生(学号,姓名,系,系主任)——系主任传递依赖于学号（学号→系→系主任），违背 3NF。拆成 学生(学号,姓名,系) + 系(系,系主任)。

1.3 三级模式与数据独立性

数据库分三级抽象，中间两级映像保证独立性。

层级别名数量作用
外模式子模式/用户模式多个用户视图，接口
模式逻辑模式/概念模式一个全局逻辑结构
内模式存储模式一个物理存储细节

逻辑独立性：模式改了，改外模式映像，外模式不变，应用不变。物理独立性：内模式（存储）改了，改模式/内模式映像，模式不变，应用不变。

1.4 E-R 模型

概念模型工具：实体（矩形）、属性（椭圆）、联系（菱形）。联系有 1:1、1:n、m:n。

三类完整性约束：实体完整性（主键不为空）、参照完整性（外键要么为空要么参照已存在）、用户定义完整性（字段有效性）。

1.5 候选码与冗余

候选码：能唯一标识元组的最小属性集（不能再删）。冗余：同一信息重复存多处。

冗余类型来源处理
有害冗余设计不规范，范式不够拆表（1NF→2NF→3NF）
可控冗余为提速主动加冗余字段配同步更新机制

冗余导致：存储浪费、更新异常（改一处漏多处）、插入异常（主键非空约束）、删除异常（删记录连带删基础信息）。

二、SQL 语言

查询 · 连接 · 权限 · 索引

2.1 命令分类

分类关键字功能
DQL 查询SELECT查数据
DML 操纵INSERT / UPDATE / DELETE增删改
DDL 定义CREATE / DROP / ALTER建库建表建索引
DCL 控制GRANT / REVOKE授/收权限

SQL 对应三级模式：外模式=视图（VIEW）、模式=基本表（TABLE）、内模式=存储文件。

2.2 SELECT 查询核心

SELECT [DISTINCT] 目标列
FROM 表名
WHERE 条件
GROUP BY 分组列
HAVING 分组后筛选
ORDER BY 排序列 [ASC|DESC];
子句作用顺序
FROM从哪张表1
WHERE行级筛选（分组前）2
GROUP BY分组3
HAVING组级筛选（分组后）4
ORDER BY排序，只能最后5

WHERE vs HAVING：WHERE 在分组前筛行，HAVING 在分组后筛组。COUNT(*) 含 NULL，COUNT(列名) 不含 NULL。

2.3 多表连接

连接方式结果
INNER JOIN只返回两表匹配的行（交集）
LEFT JOIN左表全保留，右表不匹配补 NULL
RIGHT JOIN右表全保留，左表不匹配补 NULL
FULL JOIN两表全保留，不匹配都补 NULL
SELECT 列
FROM 表1
INNER JOIN 表2 ON 表1.主键 = 表2.外键;

嵌套查询（子查询）：WHERE 里套 SELECT。EXISTS 只判断"有没有"，不关心值。

2.4 权限与索引

GRANT 授权，REVOKE 收权。WITH GRANT OPTION 允许被授权者再转给别人。CASCADE 级联收回（连转给别人的一起收）。

GRANT SELECT ON TABLE 学生 TO U1 WITH GRANT OPTION;
REVOKE SELECT ON TABLE 学生 FROM U1 CASCADE;

索引：建在表上，加速查询。CREATE [UNIQUE] INDEX 索引名 ON 表(列)。索引占空间，写时要维护。

索引类型：主键索引、唯一索引、普通索引、联合（复合）索引、覆盖索引。

三、事务与运维

ACID · 并发 · 锁 · 备份 · 性能优化

3.1 事务 ACID 与并发问题

事务 = 一组操作，要么全做，要么全不做。四个属性：

属性含义
A 原子性不可分割，全做或全不做
C 一致性执行前后，数据库从一个一致状态到另一个
I 隔离性多事务并发，互不干扰
D 持久性提交后永久生效，崩溃也不丢

并发问题：多事务同时读写，会出现四种异常：

异常现象原因
丢失修改两个事务改同一数据，后提交的覆盖先提交的写覆盖
脏读读到另一事务未提交的数据（可能被回滚）读未提交
不可重复读同一事务内两次读同一行，值不同（被 UPDATE 改了）读已提交但被改
幻读同一事务内两次查，行数变了（被 INSERT/DELETE）范围变了

不可重复读 vs 幻读：前者是值变了（UPDATE），后者是行数变了（INSERT/DELETE）。事务日志（WAL）：先写日志后写数据，崩溃可恢复。

3.2 封锁机制

锁是并发控制的主要手段。事务先申请锁，拿到锁才能操作，释放后别人才能拿。

锁别名规则
排他锁 X写锁拿到后，其他事务不能再加任何锁，独占读写
共享锁 S读锁多个事务可同时加 S 锁读，但不能加 X 锁改
更新锁 U初始化修改时加，避免死锁，确认要改再升级成 X

封锁粒度：粒度越大（整库/整表），并发越低、开销越小；粒度越小（行/页），并发越高、开销越大。短事务选小粒度，大批量选大粒度。

3.3 备份恢复

行业通用 3-2-1 原则：至少 3 份副本、2 种介质、1 份异地。

备份方式备份内容特点
全量备份整个库恢复最简单，备份慢、占空间大
增量备份上次备份后新增的变化快、小，但恢复要按顺序串
差异备份上次全量后所有变化恢复只需全量+最近一次差异
日志归档事务日志最小粒度，支持任意时间点回退

恢复分级：误删表/数据 → 用备份+日志回退；硬盘损坏 → 异地副本整库还原；机房灾难 → 跨机房灾备。

3.4 性能优化（索引+缓存+读写分离）

索引优化：索引是 B+ 树，换查询速度、占空间和维护成本。高频查询/排序/分组字段优先建索引；低区分度字段（性别、状态）别建；避免索引列上用函数/运算。

SQL 优化：别 SELECT *；用 WHERE 先缩小范围；大分页用主键回溯；小表驱动大表。

数据库缓存优化（你问的内存缓存）：磁盘 IO 是最大瓶颈，把高频热点数据、查询结果预存到内存，下次直接从内存取，不用读磁盘。

层级技术缓存什么
内置缓存InnoDB Buffer Pool数据表页、索引热点页，占物理内存 50%~80%
分布式缓存Redis热点业务数据、高频查询结果、会话数据

缓存三原则：① 只读热点优先缓存，频繁变更数据少缓存；② 设合理有效期，兼顾实时性与命中率；③ 杜绝缓存与数据库长期不一致。

其他优化：表分区（按范围/列表/哈希拆大表）、读写分离（主库写、从库读）、分库分表（垂直拆字段、水平拆行）。

四、数据仓库与挖掘

OLTP vs OLAP · 挖掘算法 · 评估指标

4.1 OLTP vs OLAP

维度OLTP（联机事务处理）OLAP（联机分析处理）
面向具体业务（存钱、下单）宏观分析（销售趋势、风险）
数据细节、当前、经常更新综合、历史、相对稳定
单次量小大
响应要求极高相对宽松

四种存储：关系库（OLTP）、数据仓库（OLAP）、图数据库（Neo4j，社交网络/反洗钱穿透）、流数据库（实时流）。

4.2 挖掘任务与算法

监督学习：有标签，预测新样本。无监督学习：无标签，发现结构。

任务类型代表算法干什么
分类监督决策树、Logistic、SVM、朴素贝叶斯预测类别（垃圾邮件？）
回归监督线性回归、岭回归预测连续值（房价？）
聚类无监督K-means、DBSCAN自动分组（用户分群）
关联分析无监督Apriori发现共购（买A常买B）
降维无监督PCA高维转低维，减少维度灾难

K-means 步骤：选 K 个中心 → 样本归最近中心 → 重算中心 → 迭代到收敛。

4.3 模型评估

二分类用混淆矩阵：

预测正预测负
实际正TP 真正例FN 假负例
实际负FP 假正例TN 真负例
指标公式含义
准确率 Accuracy(TP+TN)/总数整体猜对比例
精确率 PrecisionTP/(TP+FP)预测为正中，真对的比例
召回率 RecallTP/(TP+FN)真样本中，被找出来的比例
F12×P×R/(P+R)精确率与召回率的调和平均

ROC 曲线：横轴假正例率（FPR），纵轴真正例率（TPR=召回率）。越靠左上角越好。AUC 是 ROC 下面积，0.5=瞎猜，>0.8=好，>0.9=优秀。不平衡数据集用 AUC 比准确率稳。
