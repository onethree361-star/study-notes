网络访问控制与边界防范

考点五是"认清敌人"之后的"修墙装监控"：防火墙守边界、IDS 盯异常、扫描器定期体检、访问控制管授权。这一页的数字同样硬——防火墙两类准则、四种类型、四项功能三条局限，IDS 三类数据源，检测两派，扫描器四类，访问控制三要素三原则，每个数字都对应大纲原文，多选常考。

01

防火墙：边界上的访问控制保安

两类准则 四种类型 三条局限
小区大门保安：外面进小区要查通行证，里面往外寄大件要登记。防火墙就是网络边界上这个保安，专门在"可信任的内部网"和"不可信的公共网"之间设一道屏障。
防火墙是什么（定义）

防火墙是保护计算机网络安全的重要技术措施，是一种典型的网络边界访问控制设备。它在某个机构的网络和不安全的网络（如 Internet）之间设置屏障，阻止对信息资源的非法访问，也可以通过防火墙策略限制敏感信息、商业机密或内部数据被非法外传。

它设置在不同网络（如可信任的企业内部网和不可信的公共网）或网络安全域之间，是一系列部件的组合；在规范的网络安全架构中，通常部署为不同网络或安全域之间的主要或统一访问控制点，能根据企业的安全策略控制（允许、拒绝、监测）出入网络的信息流，且本身具有较强的抗攻击能力。

两类基本准则（答题必考，优劣别记反）
准则怎么做优点弊端
一切未被允许的就是禁止的封锁所有信息流，然后对希望提供的服务逐项开放非常实用，可以造成一种十分安全的环境安全性高于用户使用的方便性，用户所能使用的服务范围受到限制
一切未被禁止的就是允许的转发所有信息流，然后逐项屏蔽可能有害的服务构成更为灵活的应用环境，可为用户提供更多的服务网管人员疲于奔命；受保护网络范围增大时，很难提供可靠的安全防护
四种类型（技术原理分）
类型部署与位置工作原理关键特点
包过滤型（Packet Filtering）通常安装在路由器上，大多数商用路由器自带包过滤功能以 IP 包信息为基础，对 IP 源地址、IP 目标地址、封装协议、端口号等筛选；工作在 OSI 模型的网络层和传输层，检查每个数据包的头部信息决定允许还是拒绝只看包头，不看会话上下文
代理服务型（Proxy Service）由服务器端程序和客户端程序两部分构成客户端程序与中间节点连接，中间节点再与要访问的外部服务器实际连接内部网与外部网之间不存在直接连接；同时提供日志及审计服务
状态检测型（Stateful Inspection）采用状态检测包过滤机制维护动态连接表，实现网络层和传输层行为的会话级检测；除第三层网络参数外，还利用网络连接及应用服务的各种状态执行决策比传统包过滤"多记住了会话"
复合型防火墙在部分代理型或屏蔽子网结构中使用经过安全加固的堡垒主机综合采用包过滤、状态检测、代理服务等多种技术以提高访问控制和安全检测能力
功能（四条）

① 保护易受攻击的服务：过滤不安全的服务，只有预先被允许的服务才能通过防火墙；
② 控制对特殊站点的访问：控制哪些主机能被外部网络访问；
③ 集中化的安全管理：将经过修改的软件以及附加安全软件部署于防火墙设备上，实现安全能力的集中管控；
④ 对网络访问进行日志记录和统计。

局限（三条，大纲原文，一个字不能编）

① 防火墙不能防范不经由防火墙的攻击（如 U 盘、内网直连）；
② 防火墙不能防范人为因素的攻击（如钓鱼骗员工自己把数据交出去）；
③ 防火墙是被动防卫技术，对内部非法访问难以有效控制。

一句话记

默认拒绝（未允许即禁止）最安全但难用，默认允许（未禁止即允许）最方便但难防住；防火墙挡墙外，挡不住穿墙的（不经防火墙）和内鬼（内部非法访问）。

02

入侵检测系统 IDS：不拦人，只报警的监控室

动态防御 HIDS / NIDS 模式匹配
保安站门口查通行证（防火墙），监控室里还有人盯着屏幕——不拦人，但一有异常就报警。这就是 IDS：防火墙是静态隔离，IDS 是动态监测，两者是互补关系。
IDS 是什么（定义与地位）

入侵检测系统 IDS 是用于监测网络或主机活动、发现可疑行为或入侵迹象并发出告警的安全系统。入侵检测技术是网络安全领域重要的动态防御技术——相对于传统的操作系统加固技术和防火墙隔离技术等静态安全防御技术，它是一种动态的安全核心技术。

入侵检测是一个监测计算机网络和系统以发现违反安全策略事件的过程，它拓宽了传统审计的概念，以几乎不间断的方式进行检测，形成连续的检测过程。IDS 能够帮助网络系统快速发现攻击的发生，通过对计算机网络收集信息并分析，从中发现是否有违反安全策略的行为和被攻击的迹象。入侵检测的软件与硬件的组合便是入侵检测系统；与其他安全产品不同，它需要更多的智能，必须将得到的数据进行分析并得出有用的结果。

按检测数据来源分三类
类型部署与数据源查什么 / 怎么查
基于主机的 IDS（HIDS）安装在主机上；以主机的审计数据、系统日志、应用程序日志等为数据源；从主机/服务器采集操作系统日志、系统进程、文件访问和注册表访问等信息主要检测主机上的异常行为，如文件篡改、异常进程等
基于网络的 IDS（NIDS）部署在网络的关键节点；通常通过镜像端口、网络分光器或混杂模式网卡采集网络流量，对经过关键链路或关键网段的数据包进行分析通过检测网络流量识别潜在入侵行为；采用模式匹配（Pattern Matching）、协议分析等技术，将捕获的数据包与已知的攻击特征库比对，当检测到入侵行为与现有规则匹配时发出告警
分布式入侵检测系统结合分布式系统和入侵检测技术，在多个节点上同时进行检测将各节点的检测结果汇总到中央控制节点进行综合分析，实现更全面的安全监控
一句话记

防火墙是静态门禁，IDS 是动态监控：HIDS 盯单机日志与进程，NIDS 镜像流量做特征匹配，分布式把多节点结果汇到中央一起判。

03

误用检测 vs 异常检测：通缉令比脸 vs 行为反常

误用检测 异常检测 误报 / 漏报
两种抓小偷的思路：一种拿通缉令照片挨个对脸——见过的才能认，新面孔没办法；另一种看谁的行为不像这个楼里的人——没见过的也可能被抓，但容易把早起扔垃圾的老人当贼。
两种检测方法逐条对比（优点缺点别记串）
误用检测（Misuse Detection）异常检测（Anomaly Detection）
原理基于模式匹配原理，收集攻击行为的特征并建立特征库；当监控的用户行为活动与特征库中的记录相匹配时，系统将该行为判断为入侵假设入侵者活动异常于正常主体活动；先定义一组系统处于正常的数据，建立主体正常活动的"活动简档"，将当前主体的活动状况与"活动简档"比较，违反统计规律时认为可能是"入侵"行为
优点针对性强，对已知攻击检测准确能检测未知攻击
缺点只能检测已知攻击，对未知攻击无能为力难点在于如何建立准确的活动简档和设计统计算法，容易出现误报和漏报
一句话记

误用＝拿通缉令比脸，准但认不出新面孔；异常＝看行为像不像"活动简档"，能抓未知但容易误报漏报——实战两派一起上。

扫描器四类：只体检、不动手的自动化工具

Nmap Nessus 不能直接攻击
体检四步走：先量体温看屋里有哪些机器活着（网络发现）→ 再数身上有几个敞开的口子（端口扫描）→ 再查内脏有没有病灶（网络漏洞）→ 最后给胃肠单独做个镜（Web 漏洞）。扫描器的规矩是"只发现问题，不能直接攻击目标机器"。
扫描器是什么（定义）

扫描器（Scanners）是用于检测网络和主机漏洞的自动化工具，主要应用于网络安全领域。扫描器不同于一些常见的攻击工具，它只能用来发现问题，而不能直接攻击目标机器。安全扫描器是自动检测远端或本地网络和主机安全脆弱点的软件——系统管理员借此发现所维护的 Web 服务器的各种 TCP 端口的分配、提供的服务、Web 服务软件版本和这些服务及软件呈现的安全漏洞，从而做到"有的放矢"，及时修补漏洞。

四类扫描器逐条（扫什么 / 能发现什么）
类别扫什么能发现什么 / 代表产品
端口扫描器探测目标主机上开放的端口，确定哪些服务正在运行；把网络查询指令发送到目标设备或网络系统的不同端口上，分析结果检测端口是敞开的、关闭的还是过滤的敞开的端口表明可能存在安全漏洞或可通过网络非法访问的服务；端口扫描技术与漏洞扫描技术是网络安全扫描技术中的两种核心技术，如著名的 Nmap
网络漏洞扫描器远程检测目标主机 TCP/IP 不同端口的运行服务，侧重识别主机系统、网络服务层面的通用安全漏洞识别系统补丁缺失、弱口令、远程代码执行等网络层/主机层漏洞；部分综合型可附带基础 Web 漏洞检测能力，但并非其核心定位；代表 Nessus、Retina、CyberCop
网络发现扫描器（网络资产发现）通过 ICMP ping、ACK 扫描等技术探测网络中的活跃主机网络扫描是渗透测试的第一步，目的在于发现目标的操作系统类型、开放端口等基础信息，为后续的漏洞扫描工作做基础铺垫
Web 漏洞扫描器专门针对 Web 应用程序设计的自动化安全测试工具，聚焦 HTTP/HTTPS 应用层的安全风险检测，支持对 Web 站点进行持续性安全监控检测 SQL 注入、XSS 跨站脚本、文件上传等 Web 专属应用层漏洞的专用工具，检测精度和覆盖度远高于通用网络漏洞扫描器
一句话记

扫描四步顺序：先发现活机器（网络发现，渗透第一步）→ 再数开了哪些口（端口 Nmap）→ 再查系统漏洞（Nessus 系）→ 网页单独扫（Web 扫描器专管 HTTP/HTTPS）；它只"体检"不动手。

05

访问控制三要素与三原则：钥匙该怎么发

主体·客体·策略 最小特权 职责分离
门禁三问：谁要进（主体）、进哪扇门（客体）、凭什么进（策略）。再加三条发钥匙的规矩：只给干活必需的钥匙（最小特权）、开票的不能盖章（职责分离）、钥匙不仅能开门还能开"审批发布"这种高级动作（数据抽象）。
访问控制是什么（定义）

访问控制是网络安全防范和保护的主要核心策略，它的主要任务是保证网络资源不被非法使用和访问。它是一种安全手段，控制用户和系统与其他的系统和资源进行通信和交互，能够保护系统和资源免受未经授权的访问。

三个要素（S / O / A）
要素英文是什么
主体Subject（S）提出访问资源具体请求或某一操作动作的发起者；可能是某一用户，也可以是用户启动的进程、服务和设备等
客体Object（O）被访问的资源实体
控制策略Authorization（A）主体对客体的访问规则集合，直接决定主体是否可以对客体实施特定的操作
三条核心原则

① 最小特权原则（Least Privilege Principle，也称最小授权原则）：确保主体仅被授予执行任务和完成工作所必需的权限——分配给与某用户对应的角色的权限只要不超过该用户完成其任务的需要就可以了。要充分考虑主体的角色定义和岗位职责，结合业务场景分析主体在系统内的访问内容、方式、权限级别、时间限制等约束条件，并根据安全策略释放最契合业务需求又不多余的权限。在 RBAC（基于角色的访问控制）模型中，通过限制分配给角色权限的多少和大小来实现；遵循该原则可以降低安全问题的风险，并确保访问控制符合业务需求。
② 职责分离原则（Separation of Duties）：相对于不相容的权限来说，要求不相容的权限要形成相互制约的关系——一个人不能创建并审批同一条受控记录。
③ 数据抽象原则（Data Abstraction）：访问控制不应仅限于对数据对象的读写操作，还应当支持更高级别的抽象操作，如对业务对象的创建、审批、发布等操作。

大纲原话要点：RBAC 模型直接支持三个基本的安全原则——职责分离、最小权限和数据抽象。

一句话记

主体—客体—策略三要素；最小特权只给必需、职责分离不让一个人既当运动员又当裁判、数据抽象把权限从"读写"升到"创建·审批·发布"。

行 · 场景落地

16 个场景 · 点开看具体动作

同一套边界体系，写代码的人管"接口给什么权限"，运维的人管"防火墙策略怎么写"，安全岗的人管"告警怎么配"。下面按身份分组，遇到相似场景直接套动作。

组一 · 写代码 / 做系统

接口只认"登录没登录"，谁都能改别人的订单

越权三要素

订单详情接口拿到登录态就直接返回全量数据，把订单号改成别人的就能看、能改。

落地动作：每次请求同时校验"主体是谁＋对哪个客体＋允不允许"（S/O/A 三要素）；按角色收敛接口权限；加行级数据权限（只能看本人单子）。

挂的知识点：c5 访问控制三要素——控制策略直接决定主体能否对客体实施特定操作。

报销系统里，填报人自己就能点"审批通过"

职责分离不相容权限

报销单从填报到审批同一个账号全能做，自己报自己批，审计来了没法交代。

落地动作：创建人与审批人角色强制分离；审批接口校验当前用户不是单据创建人；金额超限加二级审批。

挂的知识点：c5 职责分离原则——"一个人不能创建并审批同一条受控记录"。

运维账号一把 root 密码全组共用，谁用的查不出

最小特权共享账号

图省事，全组共用一个 root，服务器上出了操作根本无法追溯到人。

落地动作：按角色（RBAC）发账号，只给完成任务必需的权限；高危操作走堡垒机、录屏留痕；权限随岗位调整及时回收。

挂的知识点：c5 最小特权原则——"权限只要不超过该用户完成其任务的需要就可以了"，RBAC 通过限制角色权限多少和大小实现。

组二 · 单位运维 / 边界建设

新防火墙策略默认全开，只封几个知名恶意域名

未禁止即允许默认拒绝

图方便上线时"转发所有信息流，逐项屏蔽有害服务"，服务越开越多，防护面失控。

落地动作：核心业务区按"一切未被允许的就是禁止的"——先封锁所有信息流，再逐项白名单开放需要的服务；每季度复核一次策略，下线过期规则。

挂的知识点：c1 两类基本准则——默认允许灵活但"很难提供可靠的安全防护"，默认拒绝安全但服务范围受限。

路由器只按 IP 和端口过滤，放行流量里藏着木马回连

状态检测包过滤局限

包过滤只看每个数据包的头部，出站 443 全放行，木马借正常端口回连根本认不出。

落地动作：边界升级状态检测型防火墙，维护动态连接表、做会话级检测；出站连接也入策略，异常外联告警。

挂的知识点：c1 四种类型——包过滤工作在网络层和传输层、只检查包头；状态检测利用网络连接及应用服务的各种状态执行决策。

内外网直连没有中转，谁访问了什么全无记录

代理服务型日志审计

内网服务器与外部网直接连通，出事想查"谁、几点、访问了哪台外部服务器"，一条记录都没有。

落地动作：外网访问走代理服务器中转，内外网之间不建直接连接；代理层开启日志及审计服务，访问记录留存可查。

挂的知识点：c1 代理服务型——"内部网与外部网之间不存在直接连接，同时提供日志及审计服务"；功能第 4 条"对网络访问进行日志记录和统计"。

领导说"上了防火墙就安全了"，U 盘和钓鱼邮件没人管

三条局限被动防卫

预算全砸在边界设备上，结果数据是员工自己用 U 盘拷出去的，还有人点钓鱼链接。

组四 · 扫描与加固

挂的知识点：c4 网络发现扫描器——"网络扫描是渗透测试的第一步"，为后续漏洞扫描做基础铺垫。

服务器 3389、22、8080 一堆端口敞着，不知道谁在用

端口扫描Nmap

管理员想知道维护的服务器开了哪些 TCP 端口、跑什么服务、软件版本号，以便"有的放矢"修缺陷。

落地动作：用 Nmap 扫一遍，按敞开/关闭/过滤分类；用不到的端口（如暴露的 3389）直接关掉；版本号已知有漏洞的限期升级。

挂的知识点：c4 端口扫描器——把查询指令发到不同端口，分析哪些端口敞开、关闭或过滤；敞开的端口表明可能存在安全漏洞。

要测政务网站有没有 SQL 注入和 XSS，该用哪种扫描器

Web 漏洞扫描器别用错工具

任务是测网站应用层的注入和跨站脚本，拿通用网络漏洞扫描器扫一遍基本白扫。

落地动作：选 Web 漏洞扫描器，针对 HTTP/HTTPS 应用层持续监控；专项扫 SQL 注入、XSS、文件上传；结果按站点建持续监控台账。

挂的知识点：c4 Web 漏洞扫描器——"检测精度和覆盖度远高于通用网络漏洞扫描器"；网络漏洞扫描器核心定位是补丁缺失、弱口令、远程代码执行这类网络层/主机层漏洞。
