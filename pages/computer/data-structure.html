数据结构

一段总括：数据结构是相互之间存在一种或多种特定关系的数据元素的集合。它由三件事咬在一起组成——逻辑结构（元素之间是什么关系）、存储结构（这层关系在内存里怎么摆）、运算（在这个结构上能做什么、做多快）。同一批数据、同一种关系，换一种摆法，操作的快慢就完全不同，所以"选数据结构"本质上是"选关系的表示方式"。

总括 1 篇 · 存储结构 4 种 · 逻辑结构 4 类 · 排序 8 种

数据结构定义

四个基本术语 · 三个面 · 抽象数据类型
01

一句话总括：数据结构 = 关系 + 摆放 + 动作

定义原文 四个基本术语 三元一体
手机通讯录人人都用过：几百个联系人，按拼音排、按首字母分栏、按最近通话排——同一批人，换一种"排法"，你要找一个号码的动作就完全不同。数据结构讲的就是这件事：数据怎么组织，决定了你怎么用它。
定义（能背就背这一段）

数据结构是相互之间存在一种或多种特定关系的数据元素的集合。它包含三个组成部分：逻辑结构——数据元素之间的抽象关系（谁挨着谁、谁是谁的上级）；存储结构——逻辑结构在计算机内存中的表示（放在哪、怎么找）；数据的运算——定义在这种结构上的操作（增、删、查、改、遍历、排序）。

一句话拆开记：数据结构 = 数据元素 + 元素间关系 + 关系上的操作。注意定义里"一种或多种特定关系"这几个字——集合、线性、树、图，差别全都在这句"关系"上。

四个基本术语：数据、数据元素、数据项、数据对象
术语定义学生信息里的例子记法
数据所有能输入计算机并被程序处理的符号总称（数字、文字、图像、声音都算）全校所有档案、成绩、照片最外层，最大的集合
数据元素数据的基本单位，通常作为一个整体来处理一条学生记录（学号+姓名+成绩）整体看待的一条
数据项数据元素中不可分割的最小单位学号、姓名、分数拆到不能再拆
数据对象性质相同的数据元素的集合，是数据的一个子集全体在校学生同款元素凑一批

考法就一种：给你三个东西，问谁是数据、谁是数据元素、谁是数据项。别把"数据元素"和"数据项"搞反——一条记录是元素，记录里的字段才是项。

一句话记

数据是材料，数据元素是砖，数据项是砖里的沙，数据对象是一批同款砖。三层套娃，从大到小，别混层。

02

三个面怎么咬在一起：逻辑、存储、运算

逻辑结构 存储结构 运算效率
同一盘棋，可以画在纸上（逻辑），也可以做成实体棋盘（存储）；棋子怎么摆，决定你伸手拿子快不快（运算）。棋盘还是那盘棋，换个做法，手感完全不同。
三个面各回答一个问题
面回答什么面向谁例子
逻辑结构元素之间是什么关系（一对一 / 一对多 / 多对多）面向问题，与计算机无关"学生按学号排成一列"
存储结构这层关系在内存里怎么表示面向机器连号座位（数组）或散坐加指路条（链表）
运算能对它们做什么、代价多大面向使用者查第 i 个、插入一个、按分数排序
三者是"一体三面"，不是三件独立的事

逻辑结构独立于存储结构：同一个"线性表"，可以存成数组，也可以存成链表——问题本身没变，机器的实现变了。
存储结构是逻辑结构的映像：内存里必须真的能表达出"相邻"或"上下级"这层语义，否则逻辑结构落不了地。
运算效率由存储结构决定：取第 5 个元素，数组一步到位 O(1)，链表得从头数 5 次 O(n)。同一个逻辑结构、同一个操作，代价差一个数量级。

一句话记

逻辑决定"是什么"，存储决定"快不快"，运算决定"合不合用"。答题时若问"为什么选这种存储结构"，答案永远落在"这个业务最常做的运算是哪个"。

03

抽象数据类型：先定"能做什么"，再谈"怎么做"

ADT 接口与实现分离 写代码直接可用
银行的取号机只承诺"取号、叫号、办理"三件事，从不管你柜台里坐几个人、用什么系统。承诺的是能力，不是做法——这就是抽象数据类型。
定义

抽象数据类型（ADT）＝ 数据对象 ＋ 数据关系 ＋ 一组基本操作。它只规定"这个类型能做什么"，不规定"底层用数组还是链表实现"。所以 ADT 属于逻辑层面的定义，与存储结构无关。

写成代码就是一张接口
ADT List {
  数据对象：D = { a_i | a_i ∈ ElemSet, i = 1, 2, ..., n, n ≥ 0 }
  数据关系：R = { <a_(i-1), a_i> | a_(i-1), a_i ∈ D, i = 2, ..., n }
  基本操作：
    InitList(&L)           // 建空表
    Length(L)              // 求表长
    GetElem(L, i, &e)      // 取第 i 个元素
    LocateElem(L, e)       // 找 e 在第几个
    ListInsert(&L, i, e)   // 在第 i 个位置插入
    ListDelete(&L, i, &e)  // 删除第 i 个元素
}  // 全篇没有一个字提"数组"或"链表"

换成 Java 的说法：List 接口规定了 add / get / remove，ArrayList 和 LinkedList 是两个实现。调用方只认接口，换实现不改一行代码——这就是抽象的意义。

考点与一句话记

考试常问"ADT 与数据结构的关系"：ADT 是逻辑层面的规格说明，数据结构是它在存储层面的具体实现。接口不变、实现随便换，这就是"抽象"。

一、物理结构（存储结构）

顺序 · 链式 · 索引 · 散列
04

四种存储结构：算出来、顺着走、查目录、哈希定位

顺序 链式 索引 散列
同样十个学生找座位：可以按学号坐连号位（顺序），可以散坐、每人手里写下一个人的位置（链式），可以散坐但门口挂一张"谁在哪"的表（索引），也可以按"学号后两位"直接算座位（散列）。四种办法，四种找人的速度。
四种办法对照表
存储方式关系怎么表示取第 i 个插入/删除额外代价典型载体
顺序存储逻辑相邻 = 物理相邻，一整块连续内存O(1) 随机访问O(n)，要挪动后面所有元素必须预留连续大块空间，扩容要整体搬数组、ArrayList、数据库页
链式存储结点 = 数据域 + 指针域，靠指针串O(n)，从头顺着走O(1)，改两个指针（已知位置）每结点多存 8～16 字节指针，缓存不友好单/双链表、树、图邻接表
索引存储数据区 + 索引表（关键字 → 地址）先查索引 O(log n)，再取数据要同步维护索引表索引本身占空间，写多时维护贵数据库索引、图书目录、字典附录
散列存储关键字经哈希函数算出存储地址平均 O(1)，最坏 O(n)扩容时全表 rehash装填因子、冲突处理、不支持范围查询HashMap、Redis 字典、布隆过滤器
一句话记

四种存储本质是四种"由关系找位置"的办法：算出来（顺序）、顺着走（链式）、查目录（索引）、哈希定位（散列）。选哪种，只看你的操作里"找"多还是"改"多。

05

顺序 vs 链式：五个维度算总账，别只看插入删除

存储密度 随机访问 链表插入一定更快？ 缓存局部性
同样一排储物柜：连续的一整排，你说"第 5 个"伸手就开；分散的柜子，每格里塞着下一格的钥匙，你得一间间开过去。但要在中间插一格，连排的得把后面全挪一遍，分散的只要改两把钥匙。
五个维度逐项比
维度顺序存储（数组）链式存储（链表）谁赢
存储密度1，空间全用来放数据小于 1，每结点要额外存指针（32 位机 4 字节 / 64 位机 8 字节，双向链表两个）顺序
随机访问按下标一步算出地址，O(1)只能从头 next 过去，O(n)顺序
插入 / 删除O(n)：后面元素整体后移或前移O(1)：改前驱和后继的指针链式（但有前提，见下）
空间弹性要预留容量，满了整体扩容并拷贝用一个申请一个，天然弹性链式
缓存局部性连续内存，CPU 一次读一整块进缓存，遍历极快每次跳指针，大概率缓存未命中（cache miss）顺序，实测差数倍
最容易错的三个判断

① "链表插入删除一定比数组快"——错。链表的 O(1) 有个前提：你已经站在要操作的那个结点上（手里有它的前驱指针 / 迭代器）。如果还得先"找到位置"，那一步是 O(n)，总账跟数组一样是 O(n)，而且链表常数更大。
② "数组插入是 O(n)，所以数组一定慢"——错。如果插入的是末尾（append），没有元素要挪，数组是 O(1) 摊销；ArrayList 的 add 就是走这条。
③ "链表省空间"——不一定。数据本身很小时（比如只存一个 int），每个结点多 8 字节指针，空间开销可能翻两三倍。

结论：按"最常做的操作"选，不按"听起来高级"选

查多改少用数组，改多且位置已知用链表；绝大多数业务是查多改少，所以 ArrayList 比 LinkedList 更常用。这句话能直接答"为什么 Java 里常用 ArrayList"。

06

真实系统里怎么选：B+ 树、哈希表、跳表、LRU

MySQL B+ 树 HashMap Redis 跳表 按操作选结构
课本上的四种存储，到了工程里会拼起来用：数据库拿 B+ 树把"查一次"压到三四次磁盘 IO，缓存拿哈希表加双向链表把"最近用的"留在手边。看懂了它们为什么这么拼，才算真懂存储结构。
MySQL InnoDB：为什么索引是 B+ 树，不是二叉树、不是哈希

B+ 树的样子：多叉平衡树，非叶结点只存键、不存数据，叶子结点存全部数据并用链表串起来；一个页默认 16KB，能装几百个键，所以三到四层就能覆盖上亿行。
为什么不用二叉树：二叉树一个结点只有两个分支，上亿数据树高 20 多层，每层一次磁盘 IO，查一行要 20 多次 IO。
为什么不用哈希索引：哈希等值查询是 O(1)，但不支持范围查询和排序——where id between 100 and 200、order by 全废。B+ 树叶子是链表，范围查询顺着叶子扫就行。

Java HashMap：数组 + 链表 + 红黑树

主体是一个数组（散列表），冲突的元素挂成链表；JDK 8 起，链表长度达到 8 且数组容量不小于 64 时，链表转成红黑树，把最坏情况的查找从 O(n) 压到 O(log n)。默认容量 16，负载因子 0.75，超过阈值就扩容一倍并 rehash。

Redis：zset 用跳表，dict 用哈希表

有序集合 zset = 跳表（多层链表，上层是下层的"快速通道"）+ 哈希表（按成员 O(1) 取分数）。选跳表而不选平衡树，是因为范围查询（ZRANGE）顺着底层链表走就行，实现也比红黑树简单。
字典 dict = 哈希表 + 渐进式 rehash：扩容时不一次性搬完，每次操作顺带搬一点，避免卡顿。

LRU 缓存：哈希表 + 双向链表

哈希表负责"O(1) 找到这个缓存项在链表里的结点"，双向链表负责"O(1) 把它移到头部 / 从尾部淘汰最久未用的"。一个负责定位、一个负责排序，两个结构拼起来才同时满足两个 O(1)。

一张选用对照
系统用的结构为什么
MySQL 索引B+ 树树矮、磁盘 IO 少、叶子链表支持范围查询与排序
Java HashMap数组 + 链表 + 红黑树平均 O(1)，极端冲突时退化用树兜底
Redis zset跳表 + 哈希表范围查询快、实现简单、按成员取分数 O(1)
LRU 缓存哈希表 + 双向链表定位 O(1) + 移动淘汰 O(1)
消息队列 / 订单超时时间轮（数组 + 链表）按时间分槽，到点扫一格，比堆更省

规律：单个结构总有短板，真实系统都是两三个结构拼起来互补。面试问"为什么这么设计"，答的就是"它要同时满足哪两个操作"。

二、逻辑结构

集合 · 线性 · 树 · 图
07

四类逻辑结构：一对一、一对多、多对多

集合 线性 树形 图形
看一群人怎么"有关系"：同一间教室的同学（只是同属一个班，没别的顺序）、排队买票的一列人（前后分明）、一家公司的组织架构（一个上级管几个人）、微信好友互相认识（谁都能连谁）。四种关系，正好对应四类逻辑结构。
四类一次分清
逻辑结构关系形态典型代表生活例子
集合结构元素之间只有"同属一个集合"，没有别的联系集合同班同学名单、黑名单里的手机号
线性结构一对一，排成一条线，有前驱后继线性表、栈、队列、串、数组排队买票、播放列表、撤销记录
树形结构一对多，有唯一根，层级分明树、二叉树、堆、B+ 树公司组织架构、文件目录、家谱
图形结构多对多，任意结点都可能相连有向图、无向图、网微信好友、地铁线路、资金流向

判别只看一句话：除首尾外每个元素有几个直接前驱、几个直接后继——0 个（集合）、1 个（线性）、≤1 个前驱但多后继（树）、任意（图）。

08

线性结构：线性表、栈、队列、串、数组

线性表 栈 LIFO 队列 FIFO 串与数组
同样是一列东西，规矩不同：抽屉可以随便抽（线性表），叠盘子只能从最上面拿（栈），排队只能队尾进、队头出（队列）。
线性表：n 个同类型元素的有限序列

除第一个元素无前驱、最后一个无后继，其余每个元素有且只有一个前驱和一个后继。两种实现：顺序表（数组，随机访问 O(1)、插入删除 O(n)）与链表（单链表/双向链表/循环链表，插入删除 O(1)、查找 O(n)）。

栈：只在一端（栈顶）操作

插入叫 push、删除叫 pop，都在栈顶，后进先出（LIFO）。两种实现：顺序栈（数组 + 栈顶指针 top）与链栈（链表头当栈顶）。
为什么到处都在用：函数调用靠它保存返回地址与局部变量（递归本质就是栈）、括号匹配（左括号入栈，右括号弹栈比对）、表达式求值（中缀转后缀）、浏览器的后退、编辑器的撤销（Ctrl+Z）。

队列：一端进（队尾）、另一端出（队头）

先进先出（FIFO）。顺序队列反复入队出队会出现"队尾到头了但前面空着"的假溢出，解决办法是循环队列：用 (rear + 1) % MAXSIZE == front 判满，牺牲一个单元区分队空队满。
用在哪：打印机任务排队、消息队列（Kafka/RabbitMQ 的模型）、BFS 层序遍历、抢票/秒杀请求削峰。

串与数组：两个"看起来简单但不能忽略"的线性结构

串是零个或多个字符的有限序列，核心操作是模式匹配（在主串里找子串）。朴素匹配最坏 O(n×m)，KMP 用 next 数组把已匹配的信息复用，做到 O(n+m)。
数组是下标与值一一对应的线性结构，重点是地址计算：二维数组按行优先存储时 LOC(i,j) = LOC(0,0) + (i × 列数 + j) × 每个元素字节数；按列优先则把 i、j 换成"行数"。这一条是纯计算题，套公式即可。

一句话记

线性表随你怎么取，栈只动最上面，队列只两头动，串在字符里找模式，数组靠公式算地址。

09

树结构：二叉树、遍历、二叉搜索树、堆

二叉树性质 三种遍历 BST 堆
公司组织架构就是一棵树：一个总经理往下分几个部门，部门再分小组。每个人只有一个直接上级，上级可以有好几个下级——这就是"一对多"。
基础术语与二叉树性质（计算题必背）

结点、根、叶子：度＝结点拥有的子树个数；度为 0 的是叶子；树的度＝各结点度的最大值；结点的层次从根算第 1 层，树的深度＝最大层次。
二叉树：每个结点至多两棵子树，且分左右（左右不能颠倒）。四条性质必须记：

性质结论怎么用
第 i 层结点数至多 2^(i-1) 个算满二叉树某层数量
深度为 k 的结点总数至多 2^k − 1 个满二叉树结点数
叶子与二度结点n0 = n2 + 1给叶子数求总度数，最常考
完全二叉树深度⌊log₂n⌋ + 1n 个结点求层高；编号 i 的左孩子 2i、右孩子 2i+1、父 ⌊i/2⌋
三种遍历：先序、中序、后序（＋层序）

先序＝根左右，中序＝左根右，后序＝左右根；层序＝从上到下一层一层，用队列实现。三条铁律：先序遍历的第一个必是根，后序遍历的最后一个必是根；给了"先序 + 中序"或"后序 + 中序"能唯一还原一棵二叉树，只给先序 + 后序还原不出来（分不清左右子树）。

二叉搜索树（BST）：查得快，但会退化

性质：左子树所有结点值 < 根 < 右子树所有结点值，且左右子树也都是 BST。查找、插入、删除平均 O(log n)，因为每比较一次就砍掉一半。
但按顺序插入会退化成一条链表（1,2,3,4,5 依次插入，树变成一条斜线），查找退化为 O(n)。解决办法是平衡树：AVL 树（严格平衡，旋转多）、红黑树（近似平衡，插入删除更快，Java 的 TreeMap、HashMap 冲突树都用它）。

堆：完全二叉树 + 堆序，专管"最值"

大顶堆：每个结点都不小于它的孩子，堆顶就是最大值；小顶堆反之。堆是一棵完全二叉树，所以能直接塞进数组，下标 i 的孩子是 2i 和 2i+1。
插入：放到末尾再"上浮"；删除堆顶：把末尾元素换到堆顶再"下沉"，都是 O(log n)。建堆从最后一个非叶结点往前下沉，整体 O(n)。用在哪：优先队列、TopK 问题（求最大 100 个用最小堆）、任务调度、堆排序。

再往上：B 树与 B+ 树（多叉，为磁盘而生）

二叉树每个结点只有两个分支，数据量大时树太高。B 树让一个结点存多个键、多个分支（m 阶 B 树每个结点最多 m 个孩子），把树高压到 3～4 层；B+ 树进一步让非叶结点只存索引、所有数据放叶子并用链表串起来，范围查询顺着叶子扫——这就是数据库索引的底层结构。

一句话记

二叉树记四条性质 + 三种遍历，BST 记"左小右大、中序有序、会退化"，堆记"完全二叉树、堆顶最值、上浮下沉"。

10

图结构：多对多，最灵活也最难算

有向/无向 完全图 邻接矩阵 DFS/BFS
地铁线路图就是一张图：站点是结点，线路是边；有的是双向（无向），有的是单向换乘通道（有向）。想知道"从 A 到 B 怎么走最快"，就是图上的最短路径问题。
基本概念（考试就考这几条）

有向图 / 无向图：边有方向叫弧（用 <A,B> 表示），没方向叫边（用 (A,B) 表示），无向边等于双向。
完全图：任意两顶点间都有边。无向完全图有 n(n−1)/2 条边；有向完全图有 n(n−1) 条弧。
度：无向图顶点 v 的度＝与它相连的边数，全部顶点度之和＝边数的 2 倍；有向图分入度、出度，入度之和＝出度之和＝弧数。
连通：无向图中任意两顶点都有路径叫连通图；有向图要求"任意两点互相可达"才叫强连通。n 个顶点的连通图至少 n−1 条边，此时就是一棵生成树。

两种存储：邻接矩阵 vs 邻接表
存储方式怎么存空间判断两点相邻遍历某点的邻居适合
邻接矩阵n×n 二维数组，有边填 1（带权填权值）O(n²)，与边数无关O(1)O(n)稠密图、点数少
邻接表每个顶点挂一条链表，存它的所有邻居O(n + e)O(该点度数)O(该点度数)稀疏图、点数大
遍历与最短路径

DFS（深度优先）：一条路走到黑，走不动再退回，靠栈/递归；BFS（广度优先）：一层一层扩散，靠队列。无权图求最短路径就用 BFS，第一次到达就是最短。
Dijkstra：单源最短路径，每次选当前距离最小的未确定顶点，要求权值非负，复杂度 O(n²) 或堆优化 O((n+e)log n)；Floyd：求任意两点间最短路径，三重循环 O(n³)，代码只有五行。

生活里的图

社交关系（好友是边，关注是有向边）、地图导航（路口是点、路是带权边）、项目依赖（A 必须先于 B，是有向无环图 DAG，拓扑排序判断能否排完）、银行资金流向（账户是点、转账是带方向的边，用来做反洗钱环检测）。树是图的特例——没有环的连通图。

同一份名单，可以写在连号的本子上，也可以写成一张张带"下一位是谁"的便签。名单还是那份名单，找人的方式变了——这就是"逻辑结构不变、存储结构可变"。

12

先看清"操作"的账本：时间复杂度、空间、稳定性

大 O 空间复杂度 稳定性
同一件事，做法不同，代价差几个数量级：100 万条数据，O(n) 扫一遍要 100 万次，O(log n) 只要 20 次，O(n²) 要一万亿次——后者根本不是"慢一点"，是跑不完。所以评价任何结构或算法，先看它落在哪一档。
三种评价口径

时间复杂度：随数据规模 n 增长，基本操作执行次数的量级。只保留最高阶项、丢掉常数系数（3n² + 5n + 7 记作 O(n²)）。
空间复杂度：除输入数据外额外占用的空间。只用几个临时变量叫原地（in-place），记 O(1)。
稳定性：排序前相等的两个元素，排序后相对次序不变，就叫稳定。判断意义：先按"成绩"排、再按"班级"排，若第二次排序稳定，同班内成绩顺序不会被冲乱。

增长速度排序（从小到大）
快到慢：O(1) → O(log n) → O(n) → O(n log n) → O(n²) → O(n³) → O(2^n) → O(n!)

能背下来的分界线：O(log n) 是"每次砍一半"（二分、平衡树）；O(n log n) 是比较类排序的理论下限；O(n²) 只适合小数据（几千条以内）；O(2^n) 以上只能处理很小规模（暴力枚举、递归不剪枝）。

一句话记

看算法先问三句：n 变大时它多快（时间）、要多占多少内存（空间）、相等元素会不会乱序（稳定性）。

13

顺序查找：从头挨个问，简单但慢

O(n) 无序也能用 数据量大就慢
找一个人，手里没有名册顺序，只能从第一间办公室开始一间间敲门问"在不在"。运气好第一间就中，运气差问到最后一间——平均问一半。
关键代码
int seqSearch(int a[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (a[i] == key) return i;   // 命中，返回下标
    return -1;                       // 走完没找到
}

// 哨兵优化：把 key 放到 a[0]，循环里就不用每次判断 i < n
int seqSearch2(int a[], int n, int key) {
    a[0] = key;                      // a[1..n] 才是数据
    int i = n;
    while (a[i] != key) i--;         // 一定会停在 0
    return i;                        // 返回 0 表示没找到
}
什么时候用

数据无序、量小、或存在链表里只能顺着走时，顺序查找就是唯一选择。它没有任何前提条件，这是它唯一的优势。
数据量上万又频繁查，还用顺序查找就是设计问题——该建索引、排序后二分，或直接上哈希表。

一句话记

顺序查找 = 逐个敲门，无序万能、代价 O(n)；平均要查一半，最坏查到底。

14

二分查找：每次砍掉一半，但前提很硬

O(log n) 必须有序 + 顺序存储 链表不能用
猜数字 1 到 100，聪明人不会从 1 开始猜，而是先猜 50："大了"就往 1–49 猜，"小了"就往 51–100 猜。每猜一次砍一半，7 次必中——这就是二分。
关键代码
int binarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {                    // 注意是 <=，区间里还有元素
        int mid = low + (high - low) / 2;    // 不写 (low+high)/2，防两数相加溢出
        if (a[mid] == key) return mid;
        else if (a[mid] < key) low = mid + 1;   // 去右半区
        else high = mid - 1;                    // 去左半区
    }
    return -1;                               // 区间空了 = 没找到
}
三个前提、三个坑

前提一：必须有序——没排序先二分，结果一定是错的。
前提二：必须顺序存储——二分要靠下标直接跳到 mid，链表只能顺着走，用不了二分。
前提三：数据不再频繁变动——每次插入删除都要维持有序（顺序表插入本身 O(n)），动态数据用二分不划算，该换平衡树或跳表。
三个坑：① while (low < high) 少了一个边界，单元素时直接漏掉；② high = mid 而不是 mid - 1，会死循环；③ mid 用 (low + high) / 2，low 和 high 都接近 int 上限时相加溢出成负数。

一句话记

二分 = 每比一次砍一半，O(log n)，前提是有序且能按下标跳；三个坑记"等号、减一、防溢出"。

15

哈希查找：不算不找，直接算地址

平均 O(1) 除留余数法 冲突处理 不支持范围查询
图书馆不按书名找书，而是给每本书算一个"架号"：书名拼音首字母转成数字，对 100 取余，余数就是架子编号。到了直接去那个架子——不用翻目录，也不用从头找。代价是：两本书可能算到同一个架子（冲突）。
哈希函数怎么设计

目标是"算得快、分布匀"。最常用除留余数法：h(key) = key % p，p 取不大于表长的最大质数（质数能减少规律性冲突）。其他还有直接定址（key 本身线性映射）、数字分析（抽几位）、平方取中、折叠法。原则是：同样的 key 永远算出同一个地址，不同的 key 尽量落到不同桶。

冲突了怎么办（两类办法）
办法做法优点缺点
开放定址·线性探测桶被占了就往后找下一个空桶（h+1, h+2…）不用额外指针、缓存友好容易"聚集"，一连串挤在一起，查找变慢；删除要打墓碑标记
开放定址·二次探测按 +1², −1², +2², −2²… 跳着找缓解聚集不一定能探到全表
链地址法（拉链）每个桶挂一条链表，冲突就挂上去冲突多也不怕、删除方便、装填因子可超过 1指针额外空间、缓存不友好
关键代码（除留余数 + 链地址）
#define M 13                       // 桶数取质数
typedef struct Node { int data; struct Node* next; } Node;

void insert(Node* ht[], int key) {
    int h = key % M;
    Node* p = (Node*)malloc(sizeof(Node));
    p->data = key;
    p->next = ht[h];               // 头插，O(1)
    ht[h] = p;
}

int find(Node* ht[], int key) {
    int h = key % M, cnt = 1;
    for (Node* p = ht[h]; p; p = p->next, cnt++)
        if (p->data == key) return cnt;   // 返回比较次数
    return 0;                             // 没找到
}
哈希的边界（最容易答错的点）

哈希查找平均 O(1)，但最坏会退化成 O(n)——所有 key 都落到同一个桶、挂成一条长链时就是这样。所以"哈希查找时间复杂度是 O(1)"这句话严格说不完整，正确说法是"平均 O(1)，最坏 O(n)"。
另一个边界：哈希表里的数据是无序的，不支持范围查询、排序、找最大最小。所以数据库有哈希索引但主索引仍然是 B+ 树。

一句话记

哈希 = 用函数把 key 变成地址，平均一步到位；代价是冲突处理、扩容 rehash、以及彻底放弃有序性。

八种排序先看总账：谁快、谁稳、谁费内存

总表 稳定性口诀 先记这张表
八个排序不是"学会八个"，而是"记住八张牌面"：谁最快、谁最稳、谁最省内存、谁最怕数据已经有序。先把牌面摊开，再一个个看它怎么打。
八种排序总表（考试就背这张）
排序最好平均最坏额外空间稳定性一句话特点
冒泡排序O(n)O(n²)O(n²)O(1)稳定相邻两两比，大的往后冒
选择排序O(n²)O(n²)O(n²)O(1)不稳定每轮挑最小的，换到队头
插入排序O(n)O(n²)O(n²)O(1)稳定像摸牌，插进手里合适的位置
希尔排序O(n log n)O(n^1.3)O(n²)O(1)不稳定先隔几个比，间隔逐渐缩到 1
归并排序O(n log n)O(n log n)O(n log n)O(n)稳定先砍到单个，再两两合成有序
快速排序O(n log n)O(n log n)O(n²)O(log n)不稳定挖个基准坑，小的甩左边

基数排序O(d(n+r))O(d(n+r))O(d(n+r))O(n+r)稳定按个位、十位、百位轮流装桶
稳定性口诀（只背这一句）

"快些选堆"不稳定——快速排序、希尔排序、选择排序、堆排序；剩下的冒泡、插入、归并、基数都稳定。
为什么这几个不稳定？一句话：它们都做了"跨距离的交换或移动"，相等元素的相对位置会被打乱；稳定的那四个都是"相邻比较、顺序挪位"。

三条一眼判断

① 要求最坏也是 O(n log n) → 归并、堆排（快排最坏 O(n²)，不能承诺）。
② 要求原地、不许多占内存 → 堆排（O(1)）；归并要 O(n) 额外数组。
③ 要求稳定 → 归并（O(n log n) 里唯一稳定的），数据量小就冒泡/插入。
快排最坏 O(n²) 的触发条件：数据已经有序（或逆序）且固定取首/尾元素做基准——这时每次划分都退化成 1 和 n−1 两段。

17

冒泡排序：相邻两两比，一趟把最大的顶到队尾

稳定 最好 O(n) 交换次数多
一队人比身高，从排头开始两两比：左边比右边高就换位。一趟走下来，全场最高的那个人一定被一路"顶"到了队尾——像水里的气泡往上冒，一趟浮出一个最大的。
最直戳的特点

每一趟只干一件事：把当前没排好的里面最大的那个，通过相邻交换送到队尾。走 n−1 趟，队尾依次填满 n−1、n−2……最后剩下一个自然最小。它的交换次数最多（平均 n²/4 次），是"慢但稳"的代表。

关键代码
void bubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {               // 一共 n-1 趟
        int swapped = 0;
        for (int j = 0; j < n - 1 - i; j++)         // 后 i 个已经排好，不用再比
            if (a[j] > a[j + 1]) {
                int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t;
                swapped = 1;
            }
        if (!swapped) break;                        // 整趟没换过 = 已经有序，提前收工
    }
}
为什么它"最好情况是 O(n)"

数据本来就基本有序时，第一趟只会做少量比较、几乎不交换；加了这个 swapped 标志，第一次发现"整趟没换过"就直接退出——所以最好 O(n)。没写这个标志的版本，最好也是 O(n²)。

稳定在哪儿：只有 a[j] > a[j+1] 才交换，相等时不换，所以相等元素的先后次序不会被打乱。

一句话记

冒泡 = 每趟把最大的顶到队尾，稳定、原地、最坏 O(n²)，是"教学用"的排序，实战基本不用。

18

选择排序：每轮只挑一个最小的，跟队头换位

交换次数最少 O(n²) 恒定 不稳定
一排人报数，你不动手排，只用眼睛扫：第一轮从头扫到尾，记住最矮的那个，让他跟排头换位置；第二轮扫剩下的，记住第二矮的，跟第二个位置换——每轮只换一次，绝不多动。
最直戳的特点

它的比较次数和交换次数是"分家"的：比较永远是 n(n−1)/2 次（不管数据长什么样），但交换最多只做 n−1 次。所以数据量大、单次交换成本高（比如元素是很大的结构体）时，它反而有优势。

关键代码
void selectSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;                         // 假设当前位置最小
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[min]) min = j;      // 只记下标，不动手
        if (min != i) {                      // 真找到更小的才交换
            int t = a[i]; a[i] = a[min]; a[min] = t;
        }
    }
}
为什么不稳定，以及"数据有序也没用"

不稳定的例子：序列 5(a), 5(b), 2，第一轮把 2 跟第一个 5 交换，变成 2, 5(b), 5(a)——两个 5 的相对次序反了。跨距离交换就是这样把相等元素的次序打乱的。

它不管数据是否有序，比较次数永远是 n(n−1)/2：已排好序的情况下，它仍然要把每一轮从头扫到尾，一趟都省不掉。这是它跟冒泡、插入最大的不同——后两者在"近乎有序"时能快起来。

一句话记

选择排序 = 每轮扫一遍挑最小、只换一次；比较恒定 O(n²)、交换最少、不稳定。

19

插入排序：像摸牌，拿到一张就往手里合适的位置塞

稳定 近乎有序时最快 小数组首选 也被快排当"收尾"
打扑克摸牌最自然：手里的牌已经按大小排好，新摸一张，从右往左比，比它大的往右挪一格，挪出来的空位就把新牌插进去。整个过程不用重排手里的牌。
最直戳的特点

它排的是"前缀已有序"这件事：第 i 轮结束时，前 i+1 个一定是有序的，后面的一概没动。所以数据越接近有序，它挪动的次数越少——最好情况 O(n)，是所有 O(n²) 排序里对"已基本排好"最友好的。

关键代码
void insertSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i];                     // 摸到的新牌先存起来（否则会被覆盖）
        int j = i - 1;
        while (j >= 0 && a[j] > key) {      // 比它大的都往后挪一格
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;                     // 空出来的位置放新牌
    }
}

注意两个细节：key 必须先备份（挪位会覆盖 a[i]）；比较用 > 不是 >=——相等就停下、插在后面，这才保证稳定。

它在实战里其实很常用

① 小数组：n < 50 时，插入排序的常数比快排小，反而更快。所以 JDK 的 Arrays.sort、C++ 的 std::sort 在递归到小片段时，会切成插入排序收尾。
② 近乎有序的数据：只有少量元素错位时，插入排序接近 O(n)，而快排反而可能因基准选不好退化。
③ 在线处理：数据是一个个来的（实时排名、日志按时间补插），插入排序能边来边排，其他排序做不到。
④ 链表：链表上做插入排序也合适——挪动只是改指针，不用整体搬家。

一句话记

插入排序 = 前缀始终有序，新元素往左找位置、大的右移；稳定、最好 O(n)、小数组和近乎有序时最快。

希尔排序：先隔几个比，间隔越缩越小，最后一轮收口

插入排序的升级版 增量 gap 不稳定
一堆乱牌要理，你不会一张张插——先按"每隔 3 张算一组"粗粗理一遍，让小牌往前跑一大步；再把间隔缩到 2、缩到 1，最后那趟几乎不用挪，因为前面已经大致就位了。
最直戳的特点

它解决的是插入排序"一次只能挪一格"的毛病：先用大间隔 gap 让元素一次跨很远，gap 逐轮减半，最后一轮 gap=1 时数据已经基本有序，插入排序只需微调。所以它比纯插入快，但比快排、归并慢一档。

关键代码（就是在 gap 上的插入排序）
void shellSort(int a[], int n) {
    for (int gap = n / 2; gap > 0; gap /= 2) {      // 增量逐轮减半，直到 1
        for (int i = gap; i < n; i++) {             // 每个位置按 gap 分组插入
            int key = a[i];
            int j = i - gap;
            while (j >= 0 && a[j] > key) {         // 同组内往前比，一次跨 gap
                a[j + gap] = a[j];
                j -= gap;
            }
            a[j + gap] = key;
        }
    }
}

把代码里所有 gap 换成 1，就是插入排序——所以希尔排序可以理解为"分组的插入排序，先让元素大跨步归位"。

增量怎么取、为什么不稳、为什么比插入快

增量序列：最简单是 n/2 逐次减半（希尔原始方案）；更好的有 Hibbard（2^k−1）、Sedgewick 序列。复杂度与增量取法直接相关，平均大约 O(n^1.3)，最坏仍是 O(n²)。
为什么不稳：gap > 1 时是跨距离移动，相等元素可能被"越过"，相对次序就乱了。
为什么比插入快：插入排序每次只挪一格，大元素要挪很多次才能到前面；希尔第一步就让它跨 gap 格，减少了总移动次数。代价是它依赖增量序列，且不稳定。

一句话记

希尔 = 带间隔的插入排序，gap 从大到小、最后一轮 gap=1 收口；原地、不稳定、平均约 O(n^1.3)，是插入排序的加速版。

21

快速排序：挖个基准当桩，小的甩左边、大的甩右边

平均最快 原地 最坏 O(n²) 不稳定
一群人按身高分队：随便挑一个人站中间当标尺，比他矮的全赶到左边，比他高的全赶到右边。然后左队、右队各自再挑一个标尺重复——分到每组只剩一个人，整队就排好了。这个"挑标尺、分两边"的动作，一次就把标尺送到了它的最终位置。
最直戳的特点

每一趟划分只保证一件事：基准元素归位，且它左边的全不大于它、右边的全不小于它。所以它不需要"合并"——分完就已经在正确的位置上了，这是它比归并省内存的根本原因。平均 O(n log n)，实测通常是最快的比较类排序。

关键代码（挖坑填数版）
void quickSort(int a[], int low, int high) {
    if (low >= high) return;                 // 区间只剩 0 或 1 个，天然有序
    int pivot = a[low];                      // 挖个坑，把基准先存起来
    int i = low, j = high;
    while (i < j) {
        while (i < j && a[j] >= pivot) j--;   // 右指针找比基准小的
        a[i] = a[j];                         // 填到左边的坑，j 处变成新坑
        while (i < j && a[i] <= pivot) i++;   // 左指针找比基准大的
        a[j] = a[i];                         // 填到右边的坑
    }
    a[i] = pivot;                            // 基准归位，i 就是它最终的位置
    quickSort(a, low, i - 1);                // 左段递归
    quickSort(a, i + 1, high);               // 右段递归
}
它最怕什么：已经有序的数组

固定取"第一个元素"当基准时，如果数组已经有序或完全逆序，每趟划分都只能分出一个长度为 1 的段，递归树退化成一条链 → O(n²)，而且递归深度达到 n，可能爆栈。
三个应对：① 随机选基准（打乱"有序"这个最坏条件）；② 三数取中（取首、中、尾的中位数做基准）；③ 小区间切插入排序（n 小于阈值时用插入，减少递归层数）。
为什么不稳定：划分时的填坑是跨距离搬动，相等元素会被换到彼此前后。要稳定就不能选快排。

一句话记

快排 = 每趟定基准位置、分两边递归、不用合并；平均最快、原地、不稳定，最坏 O(n²) 出现在数据本身有序时。

22

归并排序：先一刀刀砍到单个，再两两合并成有序

稳定 恒定 O(n log n) 要 O(n) 额外空间 能排外部大文件
两摞已经按大小理好的试卷，要合成一摞有序的：只看两摞的最上面那张，谁小先拿，拿走后露出下一张，继续比——一次就能合完，不用回头翻。归并排序就是先把一堆牌拆成一张张（每张天然有序），再这样两两合回去。
最直戳的特点

它是唯一"不管数据长什么样，都是 O(n log n)"的稳定排序。代价很明确：合并时必须借助一个和原数组等大的临时数组，空间 O(n)。所以它的取舍是"用内存换确定性"。

关键代码（分 + 合）
void merge(int a[], int l, int m, int r) {          // 合并 a[l..m] 与 a[m+1..r]
    int* tmp = (int*)malloc((r - l + 1) * sizeof(int));
    int i = l, j = m + 1, k = 0;
    while (i <= m && j <= r)
        tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++]; // 用 <= ，相等时先取左边 → 稳定
    while (i <= m) tmp[k++] = a[i++];                // 左段剩下的直接接上
    while (j <= r) tmp[k++] = a[j++];                // 右段剩下的直接接上
    for (i = 0; i < k; i++) a[l + i] = tmp[i];       // 拷回原数组
    free(tmp);
}

void mergeSort(int a[], int l, int r) {
    if (l >= r) return;
    int m = l + (r - l) / 2;                         // 取中点，防溢出
    mergeSort(a, l, m);
    mergeSort(a, m + 1, r);
    merge(a, l, m, r);                               // 先排好两段，再合并
}
稳定性靠一个等号，外部排序靠它的思路

稳定在哪儿：合并时用 a[i] <= a[j]，相等时优先取左段元素，左段的元素原本就在前面——次序保住了。写成 < 就会不稳定。

外部排序：内存装不下 10GB 数据时，归并是唯一好用的思路——先分块读进内存、各自排好写回磁盘（生成若干有序归并段），再多路归并：每次只从每个段读一小块到内存里比大小。这就是多路归并排序，数据库大表排序、大数据 Shuffle 的底层都靠它。

一句话记

归并 = 一直对半拆到底，再两两有序合并；稳定、恒定 O(n log n)、要 O(n) 额外空间，排大文件只能靠它。

23

堆排序：先堆出一座大顶堆，然后每次摘走堆顶

原地 恒定 O(n log n) 不稳定 TopK 用它
一堆人抢座位，规则很简单：每个人都不能比自己的孩子矮（父子必须"父大子小"）。这样全场最高的一定在塔尖。把塔尖的人请走、换最后一个人上去，再让他往下沉到合适位置——每请走一个，队尾就多一个排好的。
最直戳的特点

它不比较"相邻"，只维护"父不小于子"这一条局部规则；堆顶永远是当前最大值。所以取最值只要 O(1)，摘走堆顶后重新下沉只要 O(log n)——n 次摘取就是 O(n log n)，且完全不用额外数组（堆就存在原数组里）。

关键代码（下沉 + 建堆 + 逐个摘顶）
void siftDown(int a[], int i, int n) {          // 让 a[i] 下沉到合适位置
    while (2 * i + 1 < n) {                      // 还有孩子
        int c = 2 * i + 1;                       // 左孩子
        if (c + 1 < n && a[c + 1] > a[c]) c++;   // 挑更大的那个孩子
        if (a[i] >= a[c]) break;                 // 父已经不小于子，停
        int t = a[i]; a[i] = a[c]; a[c] = t;     // 跟大孩子换
        i = c;                                   // 继续往下看
    }
}

void heapSort(int a[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--)         // ① 从最后一个非叶结点往前，建堆 O(n)
        siftDown(a, i, n);
    for (int i = n - 1; i > 0; i--) {
        int t = a[0]; a[0] = a[i]; a[i] = t;     // ② 堆顶换到末尾（最大值归位）
        siftDown(a, 0, i);                       // ③ 剩下的 i 个重新维护成堆
    }
}
建堆为什么是 O(n)，以及"堆为什么不稳定"

建堆 O(n)：从最后一个非叶结点往前下沉，越靠下的结点越多、但下沉高度越短，把所有结点的下沉代价加起来是线性级（不是 n log n）。之后 n−1 次摘顶每次 O(log n)，总 O(n log n)。
不稳定：堆顶换到末尾是跨越整个数组的交换，相等元素的相对次序必然被打乱。
为什么实战比快排慢：堆排序的访问是"跳着走"（i → 2i+1），缓存命中率差；快排是顺序扫。所以同样 O(n log n)，快排的实际运行时间通常只有堆排的一半左右。

一句话记

堆排 = 建大顶堆 → 摘顶换到末尾 → 重新下沉；原地、恒定 O(n log n)、不稳定、缓存不友好，TopK 用小顶堆。

24

基数排序：按个位装一次桶、十位再装一次，装完就排好

不比较大小 稳定 O(d(n+r)) 只管整数/定长串
整理一堆三位数的档案卡，你不比大小，只按数字一位一位地分：先按个位数丢进 10 个筐，按筐号顺序收起来；再按十位数丢筐、收取；最后按百位数丢筐、收取。三趟之后，整摞卡片自然从小到大——因为你已经在每一个数位上都排过了。
最直戳的特点

它是唯一"完全不做两两比较"的排序：靠"分配"到桶里 + "收集"回来，一位一位地推进。所以它不受 O(n log n) 下界约束；但代价是必须知道数的位数、必须开足够多的桶、且只能用于整数或能按位切分的定长数据。

关键代码（LSD：从低位到高位）
void radixSort(int a[], int n) {                  // 非负整数，十进制
    int max = a[0];
    for (int i = 1; i < n; i++) if (a[i] > max) max = a[i];
    int* tmp = (int*)malloc(n * sizeof(int));

    for (int exp = 1; max / exp > 0; exp *= 10) {  // exp = 1, 10, 100 ……
        int cnt[10] = {0};
        for (int i = 0; i < n; i++) cnt[(a[i] / exp) % 10]++;       // ① 数每个桶里几个
        for (int i = 1; i < 10; i++) cnt[i] += cnt[i - 1];          // ② 前缀和 → 桶的结束下标
        for (int i = n - 1; i >= 0; i--)                            // ③ 从后往前放！才稳定
            tmp[--cnt[(a[i] / exp) % 10]] = a[i];
        for (int i = 0; i < n; i++) a[i] = tmp[i];                  // ④ 拷回，进入下一位
    }
    free(tmp);
}
三个必答的点

① 为什么必须从后往前放：同一桶内要保证"先进先出"（先收进来的排在前面），只能从后往前倒着写入。这一步是基数排序稳定的唯一保证；上一趟的次序信息全靠它传下去。
② 复杂度 O(d(n+r))：d 是最大位数（要跑几趟），n 是元素数，r 是桶数（十进制 r=10）。当 d 很小、n 很大时，它比 O(n log n) 还快。
③ 适用边界：只能排整数或定长字符串；负数要先处理符号位；浮点数不能直接按位切。空间要 O(n + r)，不是原地排序。

一句话记

基数排序 = 按位分桶、按桶收集，跑 d 趟；不比较、稳定、O(d(n+r))，只能用于整数/定长串且要额外空间。

考场上怎么选：给条件就能报出答案

决策表 四个判据 题型固定
选择题不会让你现场写八种排序，只会给一个条件："要求稳定"、"要求最坏也 O(n log n)"、"数据基本有序"、"内存只有几百 KB"——每个条件都直接指向一两个答案。这张表就是"条件 → 答案"的映射。
条件 → 选谁
题目给的条件该选为什么
"要求排序稳定"归并（大数据）／插入、冒泡（小数据）／基数（整数）稳定的只有这四个；O(n log n) 里只有归并稳定
"最坏情况也要 O(n log n)"归并、堆排序快排最坏 O(n²)，冒泡/选择/插入最坏 O(n²)，希尔最坏也 O(n²)
"辅助空间尽可能少 / 原地"堆排序（O(1)）；快排 O(log n) 次之归并要 O(n)，基数要 O(n+r)
"数据已基本有序，只少量错位"插入排序（接近 O(n)）或冒泡（带 swapped 标志）选择排序不受益，快排固定取首元素基准反而退化
"n 很小（几十个以内）"插入排序常数因子小，比快排/归并的递归开销划算
"求前 k 大 / 前 k 小"堆（求最大 k 个用容量 k 的小顶堆）只需 O(n log k)，不用全排
"数据是整数且位数固定、量很大"基数排序O(d(n+r))，可低于 O(n log n)
"内存装不下，数据在磁盘上"归并（多路归并的外部排序）只有归并能分块 + 多路合并
"没有特别要求，通用最快"快速排序平均常数最小、原地、缓存友好
四个判据，按顺序问

① 要不要稳定（要 → 归并/插入/冒泡/基数）→ ② 最坏能不能接受 O(n²)（不能 → 归并/堆）→ ③ 内存紧不紧（紧 → 堆）→ ④ 数据是不是近乎有序（是 → 插入）。四问走完，答案唯一。

三个高频错答

✗ "快排是最快的，任何情况都选它"——数据有序时它最坏 O(n²)，且不稳定。
✗ "堆排序原地又 O(n log n)，所以最好"——它缓存不友好，实测比快排慢约一倍。
✗ "归并稳定又快，用它就对了"——它要 O(n) 额外空间，嵌入式/内存受限场景用不了。

一句话记

稳定选归并、最坏选归并或堆、省内存选堆、近乎有序选插入、求 TopK 用堆、通用最快选快排。
