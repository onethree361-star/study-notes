密码技术基础及公钥基础设施

考点二是整章"怎么把 CIA 真正保住"的武器库：保密性靠加密，完整性靠 Hash 与消息认证，不可否认靠数字签名，而这一切的信任底座是 PKI 公钥基础设施。本页先把对称/非对称两套体制、RSA 与 SM2 的计算步骤、四类攻击的强度排次背熟，再落到数字信封与 PKI 怎么在网银、政务里跑起来。

三种数据变换模式、对称与非对称体制、RSA 与 SM2 计算步骤

置换·替代·代数 对称 vs 非对称 RSA 步骤 SM2 步骤
加密说穿了就是三件事：把字的顺序打乱（置换），把字换成别的字（替代），再配上数学运算（代数）。对称体制像同一把钥匙开同一把锁，快，但钥匙怎么安全递过去是难题；非对称体制是"公开挂一把锁、钥匙只有自己有"，慢，但解决了递钥匙的问题。
密码体制数据变换的三种基本模式

通常的密码体制采用置换法、替代法和代数法来进行加密和解密的变换，可以采用一种或几种方法结合的方式作为数据变换的基本模式。

置换法（换位密码）：将明文字母互相换位，明文的字母保持相同，但顺序被打乱了。例如 "helpme" 变成 "ehplem"（以两个字母为单位，组内交换位置）。

替代法（代换密码）：明文中每一个字符被替换成密文中的另一个字符，替换后的各字母保持原来位置，对密文进行逆替换就可恢复明文。例如 "fly at once" 变成 "gmz bu podf"（每个字母用下一个字母取代）。凯撒密码是一种最经典的单表移位替代密码：将明文中的每一个字母在字母表中向后（或向前）移动固定数目（密钥 k）的位置；当 k = 3 时，明文 a 被替换为 d、z 被替换为 c，明文 zhang 向后偏移 3 位即变成密文 ckdqj。

代数法：利用数学运算和代数结构对明文加密和解密，将明文中的字符（或字符块）先映射为数字，再通过模运算、矩阵运算或函数变换等代数运算生成密文，解密是相应逆运算。常见代数法包括模加法、模乘法、线性变换和矩阵变换：模 26 的字母编码体系中 a~z 表示为 0~25，明文字母对应数字加上密钥值并对 26 取模，得到密文数字再映射回字母。典型代表是仿射密码和希尔密码；希尔密码利用矩阵与向量的乘法进行加密，安全性依赖于矩阵在模运算下是否可逆。

例子：密码管理器使用时，主密码通过密钥派生函数生成加密密钥，用于加密存储的所有网站密码——这是对称加密的典型用法；非对称加密解决了对称加密密钥分发困难的问题，但一般不用于大量数据的直接加密。

RSA 计算步骤（笔记 p2，公式照抄）

原理：大数难分解——两个大素数相乘容易，反过来把乘积拆回素数极难，这是一个陷门函数。

主线：选素数 p、q → p·q = n → 算 φ(n) → 选公钥 e → 求私钥 d

一、生成密钥对（公钥、私钥）：
① 选两个大素数 p、q，且满足 p × q = n；
② 算 φ(n) = (p−1)(q−1)，选公钥 e 满足 gcd(e, φ(n)) = 1，得出公钥 (e, n)；
③ 求私钥 d：e · d mod φ(n) = 1，得出私钥 (d, n)。

二、加密 M → C：条件——明文 M < n；公式——密文 C = M^e mod n。
三、解密 C → M：公式——M = C^d mod n。

四、签名/验签（一般签的是数字指纹＝摘要）：原理是先用私钥加密、再用公钥解密来验证。① 用 (d, n)：M = C^d mod n；② 用 (e, n)：C = M^e mod n → 对比一致性。私钥和公钥的加密解密操作可逆。

笔记底部原话：A 使用 B 的公钥，在发送前将明文加密为密文再发送；传输链路中任何人都可以截获密文，但只有持有对应私钥的接收方 B 能够解密恢复明文，中间人无法从密文得到明文。

SM2 步骤（笔记 p3，国密非对称）

原理：椭圆曲线离散对数难题——已知点 G 和 P = d·G，求私钥 d 计算不可行。参数：SM2 推荐使用 256 位素域 Fp 上的椭圆曲线 y² = x³ + ax + b，基点 G 的阶为 n。

一、生成密钥对：1. 选私钥 d——随机生成整数 d，满足 1 ≤ d ≤ n−2，私钥 d 绝对保密；2. 算公钥 P：P = [d]·G = (xP, yP)，得出公钥 P（公开）。注意：RSA 的公钥是两个数 (e, n)，SM2 的公钥是椭圆曲线上的一个坐标点 P。

二、加密 M → C（明文 M 转换为比特串，长度符合要求）：1. 选随机数 k ∈ [1, n−1]；2. 算椭圆曲线点 C1 = [k]·G = (x1, y1)；3. 算 S = [h]·P（h 为余因子，通常为 1），若 S 为无穷远点则报错；4. 算 [k]·P = (x2, y2)；5. 计算密钥流 t = KDF(x2‖y2, klen)，若 t 全为 0 则返回第 1 步；6. 算密文 C2 = M ⊕ t（异或运算）；7. 算摘要 C3 = Hash(x2‖M‖y2)（Hash 通常使用 SM3）；8. 输出密文 C = C1‖C2‖C3。

三、解密 C → M：1. 从密文 C 中取出 C1，验证其满足椭圆曲线方程；2. 算 [d]·C1 = (x2, y2)（本质是 [d]·[k]·G，与加密端的 [k]·P 相同）；3. 算 t = KDF(x2‖y2, klen)；4. 算明文 M′ = C2 ⊕ t；5. 验证 C3 ≟ Hash(x2‖M′‖y2)，若相等则输出明文 M′，否则报错退出。

四、签名/验签：SM2 签名必须引入用户身份标识 ID_A 与椭圆曲线参数，生成 Z_A 值，这是区别于 RSA 签名的核心考点；Hash 通常使用 SM3。
① 生成 Z_A（预处理）：Z_A = H(ENTL_A‖ID_A‖a‖b‖xG‖yG‖xA‖yA)，其中 ID_A 为签名者身份标识（如身份证号、邮箱等），xA、yA 为签名者公钥 P 的坐标；设待签名消息为 M，计算摘要 e = H(Z_A‖M)。
② 签名（用私钥 d）：选随机数 k ∈ [1, n−1]；算 (x1, y1) = [k]·G；算 r = (e + x1) mod n，若 r = 0 或 r + k = n 则返回第 1 步；算 s = ((1+d)⁻¹·(k − r·d)) mod n，若 s = 0 则返回第 1 步；输出签名 (r, s)。
③ 验签（用公钥 P）：检查 r, s ∈ [1, n−1] 是否成立；用同样方式算 e′ = H(Z_A‖M′)；算 t = (r + s) mod n，若 t = 0 则验签不通过；算 (x1′, y1′) = [s]·G + [t]·P；算 v = (e′ + x1′) mod n；验证 v ≟ r，若相等则验签通过，否则失败。

代码视角五步（笔记 p3 右侧）

第一步 准备参数：不需要你选，直接调用国密标准——在代码里只需调用密码库（如 BouncyCastle、GmSSL），指定使用 sm2p256v1；这个标准已固定椭圆曲线方程、大素数 p、系数 a、b、基点 G(x, y)（相当于 RSA 里的模数基础）、阶 n（基点的数量，用来限制私钥范围）。
第二步 生成密钥对：你只选一个随机数——用密码学安全随机数生成器选一个 1 到 n−1 之间的随机数 d，这就是私钥；系统底层用 P = d×G（椭圆曲线点乘）算出点 P(x, y) 即公钥。伪逻辑：private_key = generate_random_number()（私钥 d）；public_key = private_key * G（公钥 P）。
第三步 加密 M → C：调用 encrypt(public_key, message)，底层依次：生成随选随机数 k → 算 C1 = k×G（把临时公钥发给对方）→ 算共享点 S = k×P（用公钥乘临时私钥）→ 由 S 推导出对称密钥流 t（KDF 函数）→ 把明文 M 和 t 异或得到密文 C2 → 把 C1、C2 和明文哈希 C3 拼在一起就是最终密文。
第四步 解密 C → M：调用 decrypt(private_key, cipher_text)，底层：取出密文里的 C1 → 用私钥算点 S = d×C1（因为 d×(k×G) = k×(d×G) = k×P，和发送方算出的是同一个共享点）→ 用 S 推对称密钥流 t → 异或还原明文 M → 用哈希验证数据没被篡改后输出明文。
第五步 签名与验签：写代码时需要多给一个参数——SM2 签名和 RSA 最大的不同，就是必须引入用户 ID！RSA 签名是直接对哈希用私钥算；写 SM2 签名代码时是 sign(private_key, message, user_id)，必须准备用户参数 ID（通常默认 "1234567812345678"，或用户身份证号）；系统底层先把 ID、公钥、曲线参数一起算出杂凑值 Z_A，再把 Z_A 和消息 M 拼一起算真正的哈希 e，然后生成随机数 k、算点 (x1, y1) = k×G，算 r = (e + x1) mod n、s = ((1+d)⁻¹×(k − r×d)) mod n，输出签名对 (r, s)。

一句话记

置换打乱顺序、替代换掉字符、代数用数学运算；对称快但钥匙难递，非对称慢但公钥随便发；RSA 公钥是 (e, n) 两个数，SM2 公钥是曲线上一个点，签名还必须带上用户 ID。

四类密码攻击按强度排序，密码体制的三类安全性

四类攻击 强度排序 三类安全性
破译者手里的牌越多，密码就越危险。只拿到密文硬猜是瞎子摸象；能自己挑明文让系统加密，等于把密码机借到手里了——所以考试最爱按"破译者知道多少"来排座次。
先分清被动攻击与主动攻击

密码分析：虽然不知道系统所用的密钥，但通过分析可能从截获的密文推断出原来明文的过程，从事这一工作的人称作密码分析员（密码分析者）。密码攻击分两类：被动攻击——对密码系统采取截获密文进行分析；主动攻击——非法入侵者主动向系统侵扰，采用删除、更改、增添、重放、伪造等手段向系统注入假消息，以达到损人利己的目的。

四类攻击：强度由低到高（笔记 p4 表格）
攻击类型攻击者掌握的信息攻击者能做什么典型场景
唯密文攻击只知道密文；不知道明文、不知道密钥只能分析截获的密文古典密码频率分析；截获一段加密报文
已知明文攻击知道若干组"明文—密文对"；明文不是自己选的利用已知对应关系反推密钥或解密新密文知道报文开头固定格式，拿已知格式比对密文
选择明文攻击知道加密算法/公钥，能调用加密接口；通常不知道私钥自己选任意明文，让系统加密，拿到对应密文有加密预言机；RSA 无填充时猜明文加密比对
选择密文攻击知道解密算法/接口，能调用解密接口；通常不知道私钥自己选任意密文，让系统解密，拿到明文或报错信息填充预言攻击；有解密黑盒可提问

大纲原文四个定义再对一遍：唯密文——有一个或多个用同一密钥加密的密文，通过分析得出明文或密钥；已知明文——除待解的密文外，还知道密文对应的部分明文；选择明文——可以得到所需要的任何明文所对应的密文，这些密文与待解的密文是用同一密钥加密得来的；选择密文——可得到所需要的任何密文所对应的明文，解密这些密文所使用的密钥与解密待解的密文的密钥是一样的。如果一个密码系统能抵抗选择明文攻击，那么它当然能够抵抗唯密文攻击和已知明文攻击。

密码体制的三类安全性
安全性判据
无条件安全无论破译者有多少密文也无法解出对应明文；即使解出了，也无法验证结果的正确性
可证明安全性证明挫败该密码学方法与某个著名困难问题（如整数素因子分解、计算离散对数）的困难程度相同
计算上安全破译的代价超出信息本身的价值，或者破译的时间超出了信息的有效期
一句话记

攻击强度由低到高：唯密文 → 已知明文 → 选择明文 → 选择密文；扛得住最强的选择明文，弱的自然不在话下；工程上真正落地的是"计算上安全"——破解花的钱比信息本身还贵。

国产密码算法 SM1 / SM2 / SM3 / SM4 / SM9

SM1 SM2 SM3 SM4 SM9
以前金融系统加密跟着国外算法走，关键时候别人留没留后门说不清楚；国密就是国家自己发布或认可的一套算法，银行、政务逐步换成"中国系统配中国密"，每个算法的类型和参数考试一个字都不能记错。
五个国密算法速记表

国产密码算法是由我国相关密码管理机构发布或认可的一系列密码算法，常见包括 SM1、SM2、SM3、SM4、SM9 等。

算法类型关键参数用途
SM1分组对称密码算法，算法细节未完全公开分组长度 128 比特，密钥长度 128 比特常用于专用安全设备中
SM2基于椭圆曲线密码体制的非对称密码算法256 位素域椭圆曲线数字签名、公钥加密、密钥交换
SM3密码杂凑算法输出杂凑值长度 256 比特数据完整性校验、数字签名等场景
SM4分组对称密码算法分组长度 128 比特，密钥长度 128 比特无线局域网、安全通信、数据加密
SM9标识密码算法，可基于用户身份标识生成公钥以用户身份标识作为公钥基础身份认证、数据加密、数字签名、密钥交换
高频陷阱

SM1、SM4 是分组对称密码算法，分组长度是 128 比特，不是 256 比特——考题里"分组长度为 256 比特"就是错项；SM1 算法细节未完全公开，只能落在专用安全设备里，和"公开算法库随便调"的 SM4 要分开记。SM9 是标识密码算法：公钥直接基于用户身份标识生成，省去了先申请证书那一步。

一句话记

对称分组 SM1、SM4（都是分组 128＋密钥 128），非对称椭圆曲线 SM2，杂凑 256 位是 SM3，SM9 拿身份标识当公钥；记法：1、4 对称，2 非对，3 杂凑，9 身份。

消息认证四要求、Hash 四特性、数字签名五设计要求

消息认证 Hash 四特性 数字签名五要求 不可否认
快递上的封条管两件事：箱子路上没被人拆过（完整性），寄件人确实是他本人（信源）。但封条谁都能贴，真要赖不掉账还得靠亲笔签名——这就是消息认证和数字签名的分工。
消息认证：证实消息来自可信源点且未被篡改

消息认证是一个证实收到的消息来自可信的源点且未被篡改的过程。两个主要目的：第一，验证信息的发送者是真正的而不是冒充的，此为信源识别；第二，验证信息的完整性，即在传送或存储过程中未被篡改、重放或延迟等。

一个安全的消息认证机制通常应满足四个要求：
① 接收者能够验证消息来源的真实性；
② 接收者能够验证消息在传输或存储过程中未被篡改；
③ 能够防止第三方伪造合法消息；
④ 必要时能够防止消息被重放或延迟使用。

普通消息认证码通常不能提供不可否认性；不可否认性通常依赖数字签名实现。因为收发双方共享同一把密钥，对方事后可以抵赖"那是你自己算出来的"。

Hash 算法四大特性（一字不能漏）

在消息认证中，Hash 函数常用于生成消息摘要，以检测消息是否发生变化。注意：单独发送"消息 + Hash 值"不能防止恶意攻击者同时篡改消息和摘要；实际应用中通常需要结合密钥形成消息认证码（如 HMAC），或者结合数字签名对消息摘要进行签名。

特性含义
正向快速给定明文 M，能在有限时间和资源内快速计算出哈希值 H(M)，保证算法实用性
逆向困难（单向性）已知哈希值 H(M)，在计算上无法反推出原始明文 M，这是"单向函数"的本质属性
输入敏感（雪崩效应）原始输入即使发生 1 比特微小变化，输出哈希值也应产生显著且不可预测的差异（约 50% 的位发生翻转）
抗碰撞性弱抗碰撞：给定 M1，难以找到 M2 使 H(M1)=H(M2)；强抗碰撞：难以找到任意两个不同消息 M1、M2 使其哈希值相同

常见 Hash 算法：MD5（已不安全）、SHA-1（已淘汰），以及 SHA-256、SHA-3、国密 SM3。

数字签名：私钥签摘要，公钥来验签

数字签名技术是公钥加密算法的典型应用：数据源发送方使用自己的私钥对数据校验和/或其他与数据内容有关的变量进行加密处理，完成对数据的合法"签名"；数据接收方利用对方的公钥来解读收到的"数字签名"，并用于数据完整性检验，确认签名合法性。技术上可以实现类似亲笔签名的身份确认、完整性验证和不可否认性；在符合法律规定的条件下，可靠的电子签名可以具有与手写签名或者盖章同等的法律效力。应用中，发送者的公钥可以很方便地得到，但他的私钥需要严格保密。

数字签名的特点：接收方能够确认或证实发送方的签字；任何人都不能伪造；如果发送方否认他所签名的消息，可以通过仲裁解决争议。

五个设计要求（背原文）：
① 可验证——保证签字是可以被确认的；
② 防抵赖——防止发送者事后不承认发送报文及签名；
③ 防假冒——防止攻击者冒充发送者，伪造带有合法数字签名的报文；
④ 防篡改——防止报文在传输过程中被第三方篡改，任何篡改都会导致签名验证失败；
⑤ 防伪造——防止接收方或第三方伪造合法的数字签名，伪造的签名无法通过验证。

与普通消息认证的区别：消息认证通常能够验证消息来源和完整性，防止第三方伪造或篡改，但基于共享密钥的消息认证码一般不能提供不可否认性；数字签名使用发送者私钥生成签名，任何人都可以使用其公钥验证，因此除完整性和身份认证外，还能提供不可否认性，可用于解决事后抵赖问题。

一句话记

Hash 四性：正向快、逆向难、输入敏感、抗碰撞；签名五性：可验证、防抵赖、防假冒、防篡改、防伪造；记住"HMAC 不认账，私钥签名才赖不掉"。

数字信封、PKI 组成与工作流程、量子密钥分发

数字信封 PKI 组成 CA·RA·证书库 QKD
寄贵重物品：大箱子（数据）用便宜的对称锁锁上，钥匙塞进信封、用对方的公锁封死一起寄；对方先用自己的私钥拆信封拿到钥匙，再开箱子——这就是数字信封。而"怎么证明这把公锁真是你的"，就得靠 PKI 这个第三方公证处（CA）给公钥盖章背书。
数字信封：对称密钥加密正文，公钥加密对称密钥

在数字信封技术中，信息发送方采用对称密钥来加密信息内容，然后将此对称密钥用接收方的公开密钥来加密（这部分称数字信封），之后将它和加密后的信息一起发送给接收方；接收方先用相应的私有密钥打开数字信封，得到对称密钥，然后使用对称密钥解开加密信息。这种技术的安全性相当高。

打包：发送方用对称密钥加密正文 → 用接收方公钥加密该对称密钥（数字信封）→ 加密正文＋数字信封一起发出
拆解：接收方用私钥打开数字信封 → 还原对称密钥 → 对称密钥解开加密正文

两个术语：数字信封打包——使用对方的公钥将加密密钥进行加密的过程，只有对方的私钥才能将加密后的数据（通信密钥）还原；数字信封拆解——使用私钥将加密过的数据解密的过程。

PKI 是什么：用公钥密码搭起来的信任体系

公钥基础设施（PKI, Public Key Infrastructure）是一种遵循标准规范，利用公钥密码技术为网络应用提供加密和数字签名服务的体系架构。PKI 通过数字证书管理公钥，通过第三方可信机构验证用户身份，解决了大规模网络环境中公钥的真实性和完整性问题；作为现代信息安全的基石，广泛应用于电子商务、电子政务、网络安全通信等领域。三个主要特点：节省费用（大型组织实施统一安全方案比多个零散方案省钱得多）、互操作性（每个应用程序和设备以相同方式访问和使用基础设施）、开放性（国际标准公认的技术比专有点对点方案更可信方便，点对点方案不能处理多域间复杂性）。

PKI 的组成（五大块）

PKI 由公开密钥密码技术、数字证书、认证中心（CA）和关于公开密钥的安全策略等基本部分共同组成。一个完整的 PKI 产品通常包含：

组件干什么
最终实体 EE 与数字证书EE 即 PKI 中的用户；其公钥和标识信息由可信机构安全绑定即成为数字证书，EE 是证书主体。分两类：证书持有者（证书标明的用户）、依赖方（依赖证书真实性的用户，在数字签名中即在相信证书真实性基础上验证签名者）
CA 认证中心可信权威机构，负责颁发、管理和吊销最终实体的证书，最终负责所有最终实体身份的真实性
RA 注册中心可选的管理实体，主要负责最终用户的注册管理，被 CA 所信任
证书库 repository证书的集中存放地、网上公共信息库，用户可从此获得其他用户的证书和公钥；最佳方法是采用支持 LDAP 协议的目录系统，通过 LDAP 访问；必须确保证书库完整性，防止伪造、篡改证书
证书作废处理系统PKI 的重要组件；证书在有效期内也可能需要作废（如职员辞职需终止其证书生命期）

作废证书有三种策略：① 作废一个或多个主体的证书；② 作废由某一对密钥签发的所有证书；③ 作废由某 CA 签发的所有证书。

PKI 工作流程

证书申请流程：用户首先生成密钥对 → 向 RA 提交证书申请、提供身份证明材料 → RA 验证通过后将申请信息传送给 CA → CA 进行最终审核并签发证书 → 将证书发布到目录服务器，确保公钥与真实身份可靠绑定。
证书验证过程：包括检查证书链、验证 CA 签名、确认有效期和检查吊销状态；系统沿证书链追溯到可信根 CA，使用 CA 公钥验证证书签名有效性，同时检查证书是否在有效期内，并通过 CRL 或 OCSP 确认证书未被吊销。
密钥生命周期管理：覆盖生成、存储、分发、更新、备份和销毁；硬件安全模块为密钥提供安全存储环境，密钥归档服务确保加密数据的长期可访问性；对于加密密钥，可根据业务需要安全备份或归档；对于签名私钥，应严格控制复制和备份，防止影响签名的不可否认性。

场景怎么用证书
安全电子邮件通过 S/MIME 协议用数字证书对邮件签名和加密：发送方私钥签名、接收方用发送方公钥验证；用接收方公钥加密、接收方私钥解密
安全 Web 访问HTTPS 基于 PKI 实现网站身份认证和传输加密；服务器证书验证网站身份，SSL/TLS 握手建立安全通道；扩展验证证书提供更严格验证的组织身份信息，具体显示方式取决于浏览器和客户端实现
虚拟专用网络IPSec VPN 使用数字证书进行设备认证和密钥交换，建立站点到站点通信隧道；远程接入用户通过客户端证书认证身份

量子密钥分发 QKD

量子密钥分发（QKD）是物理学与计算机科学领域中一种确保通信安全的方法，允许通信双方生成共享的随机秘密密钥；量子密钥分发可以让空间分离的用户共享无条件安全的密钥，这是经典通信无法完成的任务。

一句话记

正文用对称密钥、对称密钥用对方公钥封进信封；公钥真不真找 CA 背书，离职立刻吊销（CRL/OCSP）；QKD 干的事就一句话——把无条件安全的密钥分给相隔两地的人。

组一 · 写代码 / 做系统

登录密码表存的就是 MD5，拖库等于裸奔

MD5 已不安全单向性·抗碰撞

后台 password 列存一串 32 位 MD5，开发说"单向哈希了，很安全"。实际上彩虹表一撞一个准。

落地动作：登录口令绝不明文、也不用 MD5/SHA-256 这类快哈希裸存，改用 bcrypt/Argon2 慢哈希＋每用户随机盐；校验用恒定时间比较，防时序侧信道；就算拖库，攻击者也撞不动。

挂的知识点：Hash 四特性里的"逆向困难（单向性）＋抗碰撞"；MD5 已不安全、SHA-1 已淘汰（c4）。

给全接口套 RSA 加密，报文慢得像蜗牛

对称效率高非对称不加密大数据

架构师说"非对称更安全，所有报文都 RSA 加一遍"，实测一个订单接口凭空多了 200 毫秒。

落地动作：大批量正文一律对称加密（AES，128/192/256 位密钥）；非对称只干两件小事——交换会话密钥、做数字签名；拿对方公钥加密一次性对称密钥当信封，和密文一起发。

挂的知识点：对称加密效率高但密钥分发难，非对称解决分发但计算复杂度高、不直接加密大量数据（c1）；数字信封思路（c5）。

服务回调加签，用 HMAC 还是私钥签名

消息认证四要求MAC 不能不可否认

支付回调要防第三方伪造，团队纠结到底加哪种签，两种都上又嫌慢。

落地动作：内部系统互调用 HMAC（共享密钥＋时间戳＋随机串，快）；对外、要担责的报文（付款、合同）用 SM2/RSA 私钥签摘要，对方用我方公钥验；时间戳设 5 分钟窗口、流水号唯一，防重放。

挂的知识点：消息认证四要求（验来源、验未篡改、防第三方伪造、防重放延迟）；普通消息认证码不能提供不可否认性，要赖不掉就用数字签名（c4）。

官网"文件＋MD5"放同一目录，校验等于没做

连摘要一起被改摘要要签名

官网下载目录里安装包旁边放了个 md5.txt，攻击者替换安装包时顺手把 md5.txt 也改了。

落地动作：摘要升级为 SM3/SHA-256；摘要用开发者私钥签名后再发布，或只走 HTTPS 官网下发；别把摘要和被校验文件放同一个可篡改位置。

挂的知识点：单独发送"消息＋Hash 值"挡不住同时篡改消息和摘要，必须配密钥（HMAC）或配数字签名（c4）。

手搓教科书版 RSA 不做填充，还回详细报错

选择密文攻击标准填充

为了"轻量"，加密就裸算 C=M^e mod n；解密一失败就返回"padding 错误"，等于给攻击者递答案。

落地动作：直接用密码库的标准填充（加密用 OAEP、签名用 PKCS#1 v1.5），别自己写模幂；解密服务只回"成功/失败"二值，不给任何细节报错，堵住填充预言攻击。

挂的知识点：四类攻击里最强的选择密文攻击——能调用解密接口、还能从报错信息里出题（c2）。

组二 · 网银 / 支付业务

转账报文在路上，怎么保证金额没被改一位

数字签名防篡改·防假冒

手机银行把金额、账号、流水号 POST 到银行，中间链路可能被抓包改数。

落地动作：报文字段按固定字典序拼接，商户私钥做 SM2/RSA 签名，银行端用商户公钥验签；验签失败直接拒单并告警；流水号唯一＋时间戳窗口防重放。

挂的知识点：数字签名五个设计要求——可验证、防篡改、防假冒、防伪造（c4）。

网银 U 盾里到底存了什么，丢了怎么办

私钥不出盾证书吊销

客户在柜面问"我这 U 盾是不是把网银密码存里面了"，柜员答不上来。

落地动作：私钥在盾内生成、永不出硬件，交易时在盾内完成签名；电脑里只装证书和公钥；客户报失立刻作废证书、加入 CRL，OCSP 同步吊销状态。

挂的知识点：最终实体与数字证书——公钥可方便得到、私钥严格保密；证书作废处理系统（c5）。

每天上万笔报文，对称密钥怎么安全换

数字信封会话密钥

长期用同一把对称密钥，怕一旦泄露全完；派人线下送钥匙又不现实。

落地动作：每笔会话随机生成一次性对称密钥加密正文；用对端公钥加密该密钥做成数字信封随报文发出；对端私钥拆信封还原会话密钥，用完即弃。

挂的知识点：数字信封打包与拆解——对称密钥加密正文、公钥加密对称密钥（c5）。

电子回单事后客户说"这不是我签的"，拿什么仲裁

不可否认纠纷举证

客户事后否认一笔电子回单，银行要举证，结果系统里只留了个双方共享的 MAC 值。

落地动作：回单用客户私钥对 SM3 摘要做数字签名留存，同时留存证书链与时间戳；纠纷时任何人可用客户公钥验签，通过即可仲裁——别用共享密钥 MAC 留证，它没有不可否认性。

挂的知识点：数字签名额外提供不可否认性、可仲裁；消息认证码一般不能提供不可否认性（c4）。

组三 · 运维与单位管理

员工离职当天，他那张数字证书怎么处置

证书作废三策略证书还有三个月有效期

开发提了离职，他的 VPN 证书三个月后才到期，这三个月里谁都能拿它登录。

落地动作：离职当天注销其证书并加入 CRL，OCSP 同步吊销状态；怀疑整对密钥泄露时，作废该对密钥签发的所有证书；只有 CA 私钥出事，才走到最后一档——作废某 CA 签发的所有证书。

挂的知识点：证书作废三种策略（c5）。

两台内网机器互认，怎么确认对面真是它

证书验证四步IPSec VPN

数据库只允许应用服务器连，可应用服务器证书是自签的，跨部门互联时谁也不敢信谁。

落地动作：设备持客户端证书；验签时沿证书链追溯到可信根 CA、验 CA 签名、查有效期、OCSP 实时查吊销状态；跨机构互联统一走受信任 CA，互不信任自签证书。

挂的知识点：证书验证——证书链、CA 签名、有效期、吊销状态；IPSec VPN 用数字证书做设备认证和密钥交换（c5）。

等保商密改造，算法选型怎么一张表答完

SM2SM3SM4

监管要求核心系统逐步替换为国产密码算法，列选型表时容易张冠李戴。

落地动作：大量数据加密选 SM4（无线局域网、安全通信、数据加密）；完整性校验选 SM3（256 比特杂凑值）；签名与密钥交换选 SM2；SM1 因算法细节未完全公开、只落在专用安全设备；跨机构海量身份认证场景评估 SM9。

挂的知识点：国密五算法的类型、参数与用途对照表（c3）。

备份时，签名私钥和加密密钥能不能一起拷

签名私钥严控复制HSM

为了防丢 key，运维把所有密钥都拷了一份离线盘，包括用来签合同的那把私钥。

落地动作：加密密钥可安全备份或归档，保证历史加密数据还能解开；签名私钥严格控制复制和备份——多一份拷贝就多一份冒名签名的风险；私钥放进硬件安全模块（HSM）。

挂的知识点：密钥生命周期管理——签名私钥严格控制复制和备份，防止影响签名的不可否认性（c5）。

组四 · 个人用网 / 生活

几十个网站密码一模一样，一次泄露全站遭殃

密码管理器密钥派生

一个小论坛被拖库，因为密码复用，邮箱和网银同一天被撞库登录。

落地动作：装密码管理器，主密码又长又唯一；主密码经密钥派生函数生成加密密钥，自动为每个网站生成不同随机密码并加密保管，登录自动填充。

挂的知识点：对称加密效率高——密码管理器用主密码派生密钥，统一加密存储各网站密码（c1）。

网银页面弹出"证书有风险，是否继续访问"

仿冒钓鱼证书验证

浏览器地址栏不是安全锁，点开"高级"提示证书不被信任，页面长得跟真网银一模一样。

落地动作：绝不点"继续访问"，立刻关页面；手动核对域名拼写；看证书颁发者是不是可信 CA、是否在有效期；真有事先打银行官方客服电话核实。

挂的知识点：证书验证——验 CA 签名、有效期、吊销状态；HTTPS 基于 PKI 验证网站身份（c5）。

从第三方站下软件，官网给的校验值怎么验

雪崩效应MD5 别用了

官网公告给了一串 SHA-256 值，怕下到被人改过的版本，又不知道怎么比对。

落地动作：下载后本地跑校验（certutil -hashfile 文件名 SHA256，或 shasum -a 256），和官网公布值逐位比对；校验值只从官网或官方公告拿；别再用 MD5 校验完整性——它已不安全。

挂的知识点：Hash 输入敏感（雪崩效应）——改一个字节哈希值就全变；MD5 已不安全，SM3/SHA-256 才可信（c4）。

打印店电脑登网银，U 盾插上去就有残留吗

私钥严格保密公共电脑

在打印店急用网银查流水，把个人 U 盾插进了别人的电脑。

落地动作：公共电脑不插个人证书介质；必须用时办完立刻拔盾、退出登录；个人证书申请时就把私钥标记为"不可导出"；回家后改重要账户密码。

挂的知识点：数字签名应用中发送者公钥可方便得到、私钥需严格保密；私钥不可导出是证书申请时的关键选项（c4、c5）。

组五 · 面试 / 监管检查

面试问"对称和非对称有什么区别，实际怎么搭配"

面试对比表

这题最容易答成"一个快一个慢"，考官听完记不住。

落地动作：先按对比表答——密钥是否相同、效率、分发难题、典型算法（AES 支持 128/192/256 位 vs RSA）；再给搭配话术：非对称负责安全地把对称密钥送过去，对称负责高效加密大批量正文——这就是数字信封。

挂的知识点：对称/非对称对比表（c1）＋数字信封（c5）。

监管问"怎么证明报文没被改、客户也赖不掉"

监管检查闭环答法

金融监管局现场检查，第一个问题就是这个，只答"我们用了加密"等于没答。

落地动作：分两层——完整性用 SM3 摘要，不可否认用 SM2 私钥签名；验签四动作闭环：验证书链到根 CA、验 CA 签名、查有效期、CRL/OCSP 查吊销；主动说明 MD5/SHA-1 已淘汰，系统在用 SM2/SM3/SM4。

挂的知识点：数字签名五要求＋消息认证四要求＋PKI 证书验证四步（c4、c5）。

面试问"量子计算出来了，现在 RSA 还安全吗"

面试三类安全性QKD

面试官顺着国密聊到未来，考你知不知道"安全"这件事本身是怎么定义的。

落地动作：先定性——RSA/SM2 属于可证明安全：破解它等价于大整数素因子分解、椭圆曲线离散对数这类困难问题；再补 QKD：量子密钥分发能让空间分离的双方共享无条件安全的密钥，这是经典通信做不到的；收尾一句：现阶段工程上仍按计算上安全选型，后量子密码是演进方向。

挂的知识点：三类安全性（无条件安全、可证明安全、计算上安全，c2）＋QKD 的定位（c5）。
